## 1. Goal and boundary

Before the M3 production card-save loop, M2.1 completes two local-continuity capabilities: automatically restoring the user's last input and saving the complete current content as a reusable user template. First catalog initialization creates an ordinary “海棠仙” template; when no valid recent draft exists at that point, the editor uses it as startup content.

This work does not change scoring, Archive Schema v2, desktop rating-structure templates, cover compression, card ratios, or JSBridge permissions. As an M2.1 UI closure, the MiniTool allows one to twelve positive items to be added or removed and replaces icon-shape descriptions with neutral scoring terms. “Long-term” means surviving normal close/reopen while the same MiniTool local storage remains; it is not a cloud backup or permanence guarantee.

## 2. Frozen product behavior

### 2.1 Startup precedence

```text
Read recent draft, template catalog, and one-time seed marker
  ├─ valid recent draft: restore it (highest priority); if unseeded, only create ordinary “海棠仙” template
  ├─ no draft and unseeded: create and apply ordinary “海棠仙,” then record seeded state
  ├─ no draft and seeded: create blank Simple draft; never recreate renamed/deleted template
  ├─ damaged draft: quarantine and warn; choose first template or blank draft from seed state
  └─ unavailable storage: load “海棠仙” startup content in memory and show unsaved state
```

“海棠仙” is created only when the seed marker is absent and receives no special permissions afterward. Rename/delete never clears the marker, so normal reopening cannot restore it; clearing all MiniTool local data starts a new first initialization. Automatic first application needs no confirmation; any later explicit template application replaces current editor content and requires confirmation.

### 2.2 Recent draft

- Persist all current text, scores, reasons, mode, and work fields with the existing 300 ms debounce, plus a best-effort synchronous save on page hide/close.
- Show local save state after success. On failure, retain in-memory edits and never claim they were saved.
- Recent draft and template catalog use separate keys and validators; corruption of either must not clear the other.
- The M2 compressed cover remains a memory-only Blob URL and is not written to a recent draft or content template.

### 2.3 Content templates

- The initially created “海棠仙” is identical to every other content template and may be applied, renamed, replaced, or deleted.
- Users can save current content, apply, rename, and delete templates; there is no Built-in/read-only state.
- Trimmed names are 1–40 characters and same-name matching uses the normalized name. Same-name replacement and deletion require confirmation.
- Store at most 20 content templates including the initial “海棠仙,” and at most 512 KiB of serialized catalog data. Limit/quota failure leaves the previous catalog unchanged.
- Sort every entry by most recent update; no template is permanently pinned.
- The first release has no template-file import/export, cross-device sync, or persisted template cover.

## 4. Data and implementation design

### 4.1 Storage keys

| Data                          | Key                                              | Version     |
| ----------------------------- | ------------------------------------------------ | ----------- |
| Recent draft                  | `xdrate.music.minitool.workspace.v1`             | existing v1 |
| Content-template catalog      | `xdrate.music.minitool.content-templates.v1`     | new v1      |
| One-time template seed marker | `xdrate.music.minitool.content-template-seed.v1` | new v1      |

Catalog entries use `format: 'xdrate-music-minitool-content-template'`, `schemaVersion: 1`, stable ID, name, ISO creation/update times, and a cover-free `MusicRatingDraft`. The source constant is used only for first seeding. Write the independent seed marker after the catalog write succeeds. Rename/delete updates only the catalog and never clears the marker; an initialization retry that finds the stable seed ID must not duplicate it.

### 4.2 Module split

```text
src/minitool/fixtures/haitangxianTemplate.ts
  └─ frozen cover-free fixture used only for first seeding

src/minitool/contentTemplates.ts
  ├─ strict validation and cover-free deep clone
  ├─ load / create / rename / delete / replace
  └─ count, name, and 512 KiB budget gates

src/minitool/main.tsx
  ├─ startup precedence and status messaging
  └─ template list, save, apply, rename, and delete UI
```

If implementation exports the draft validator from `storage.ts`, it may export only a pure validator and must not weaken current input boundaries. Reuse the Chrome 61-compatible ID fallback; add no network, IndexedDB cover store, or hard dependency on modern runtime APIs.

## 5. Work packages and order

- Add the frozen “海棠仙” fixture and stable IDs.

### V03-TPL-03: mobile UI and startup wiring

- Add a compact template panel, name field, save/apply/rename/delete actions, and bilingual state copy.

- Allow one to twelve positive items to be added or removed; either action enters Custom mode. Headings, buttons, help, status, and accessible names describe scoring semantics rather than icon shapes.
- At 360 px, every action remains touch-reachable without horizontal scrolling. Confirm only destructive replacement/deletion actions.

### V03-TPL-04: regression and evidence
