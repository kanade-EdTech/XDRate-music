## 1. Delivered

- The MiniTool UI no longer exposes the internal milestone label and now displays the user-facing `MINI TOOL v0.3.0` identity.
- Bilingual privacy copy distinguishes container-local cache, system-album save, and direct publishing. The app does not use the network or publish notes; it hands the PNG to the system album only after an explicit Save action.
- `npm run minitool:pack:m4` now runs ZIP-verifier negative tests, the Chrome 61-targeted build, semantic audit of the unpacked directory, deterministic packaging, and exact final-ZIP verification.
- The final-ZIP verifier checks central-directory bounds, path traversal, duplicate entries, encryption/compression method, allowed extensions, the unique root `index.html`, CRC, the SHA-256 sidecar, and byte-for-byte parity with the audited `dist-minitool` directory.
- A machine-readable manifest records version, channel, SHA-256, source commit/dirty state, per-file sizes and hashes, privacy boundaries, and known limitations.
- A complete one-to-twelve positive-item E2E boundary test was added. Add is disabled at twelve, Remove is disabled at one, and Custom mode survives draft restoration.
