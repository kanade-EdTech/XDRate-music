# V0.3.1 M2 Post Confirmation and Recovery Execution Log

## 1. Outcome

M2 connects the narrow M1 `postNote` Bridge to a bilingual post-confirmation screen. A user must first generate a rating card, review or edit the title, body, tags, and pending image, and then use one explicit final action to enter Xiaohongshu's native posting flow.

An `accepted` Bridge result means only that the native posting flow accepted the handoff; it is not proof that the post became public. The current output remains a v0.3.1 engineering build, not a real-device-accepted candidate ZIP, and it must not overwrite or repack the frozen v0.3.0 RC.1.

## 2. Confirmation and data boundary

- The title defaults to the work title, the body defaults to the overall review plus personal story, and tags default to empty. All three are editable.
- The title is limited to 20 Unicode code points and the body to 1,000. Counting, truncation, and final serialization share the rules in `postNotePayload.ts`, so surrogate-pair characters are not split.
- The screen shows the current generated rating-card PNG, live counts, and an explicit privacy disclosure.
- Local editing and opening confirmation never invoke `postNote`. Only “Continue to Xiaohongshu” performs one native invocation.
- The payload uses fixed `photo_publish` media with the locally generated complete PNG data URI. No application server receives the data, and the app reads neither the album nor account information.

## 3. Persistence before handoff

The final action synchronously writes two separate records before native invocation:

1. the complete current workspace using the existing recent-draft storage; and
2. a versioned pending-post record at `xdrate.music.minitool.pending-post.v1`, including title, body, tags, and complete image data.

If either write fails, the UI reports an actionable storage failure and blocks the Bridge call. The user is never navigated away before recoverability is established.

## 4. Cancellation, failure, and return

| State            | User-visible meaning                             | Content behavior                                            |
| ---------------- | ------------------------------------------------ | ----------------------------------------------------------- |
| `accepted`       | Entered Xiaohongshu's posting flow               | Confirmation remains available; no public-publication claim |
| `cancelled`      | Cancelled; editing or retry remains possible     | Title, body, tags, and image all remain intact              |
| `failed`         | Invocation failed; the user may retry explicitly | All content remains; no silent retry                        |
| `storage-failed` | Safe persistence failed; posting was not entered | Content remains and native invocation count stays zero      |

On reload, the pending record is validated and restores both the full confirmation and its rating-card preview. Corrupt, image-less, or version-mismatched records never become submittable.
