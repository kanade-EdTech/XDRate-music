## 2. Cover compression policy

- Accept PNG, JPEG, and WebP only; reject files over 20 MiB before decoding to avoid an obvious memory spike.
- Load with `URL.createObjectURL()` and revoke the original URL immediately after decoding.
- Preserve aspect ratio through Canvas 2D, starting at a 1280 px maximum edge, then 1024 and 768 px if needed.
- Prefer WebP at quality 0.84, 0.72, and 0.60; target at most 512 KiB and retain the smallest successful result as fallback.
- Preview only the compressed Blob URL and revoke it on replacement, removal, or unmount. Reset the encoding canvas to 1×1 after use.
- Show output dimensions, KiB, and MIME type. Invalid type, over-limit source, decode failure, and encode failure have recoverable copy.
- M2 does not write cover Base64 into localStorage; a cover must be selected again after reload. This is an explicit memory boundary, not a permanent-backup claim.

## 3. Touch, keyboard, and safe area

- Positive and deduction controls use a single flexible row. Positive-score hit regions are 55 CSS px high, with a compact axis-name field, so a 360 px viewport needs no horizontal drag.
- Forms and primary controls are at least 44 CSS px high, visible on touch, and never hover-dependent.
- When available, `visualViewport` maintains `--app-height` and `--keyboard-offset`; otherwise `window.innerHeight` is the baseline.
- A soft keyboard is inferred only when the layout/visual height delta is at least 120 px, avoiding small browser-chrome changes.
- Focused form controls scroll toward the visual center after 180 ms, with `scrollIntoView(false)` as the old-call fallback.
- A material width change resets the viewport baseline so orientation changes do not retain the old direction height.
- Safe area keeps ordinary padding first, then uses `var(--safe-area-inset-*, env(..., 0px))` for both simulator-injected variables and device `env()`.
- While the keyboard is open, the auto-save state remains sticky and bottom padding includes the keyboard offset.
