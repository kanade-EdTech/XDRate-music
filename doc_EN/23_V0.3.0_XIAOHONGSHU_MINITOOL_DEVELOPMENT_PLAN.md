# V0.3.0 Xiaohongshu MiniTool Development Plan

Status: plan frozen; M4 static candidate preflight is active; source-freeze and multi-device gates still block a public candidate<br>
Target version: `0.3.0`<br>
Target artifact: Xiaohongshu MiniTool offline ZIP<br>
Prerequisite baseline: rating domain, card model, and bilingual copy frozen by Web v0.1 and Windows v0.2

## 1. Version position

v0.3.0 is the Xiaohongshu MiniTool edition. It is neither a native Android/iOS app nor a direct port of the desktop installer. The former v0.3 standalone-mobile plan moves in full to v0.4.0.

This version retains “多维音乐评价 / `XDRate Music`” and adds a “Xiaohongshu MiniTool” carrier label in release material. Desktop/native identifiers such as `com.xdrate.music` and `XDRate.Music` do not identify the ZIP. The platform package identity will be registered through the official publication flow and must not be presented as an Android `applicationId`.

The scoring algorithm remains `music-linear-100-v4`, with a 0–100 aggregate displayed to one decimal. Archive Schema remains v2. Platform adaptation must not change scores, weights, unrated semantics, or the eleven card ratios.

## 2. Core user loop

1. Enter work metadata, whole-number positive items, deduction items, reasons, and narrative in the MiniTool.
2. Save the draft in container-local storage and make a best effort to restore it after reopening.
3. Use the same card view model and layout plan for preview and final output.
4. Generate a PNG Data URI locally after an explicit Save action.
5. Call `window.xhs.miniTool.writeTempFile`, then `saveImageToPhotosAlbum`, through a platform adapter and user authorization.
6. Report success, cancellation, denied permission, insufficient space, and unavailable bridge without losing current edits.

The default flow performs no network request. Saving to the photo album is an explicit local-device action, not an upload or publication.

## 3. Scope

### 3.1 Required

- Simplified Chinese and English editing UI;
- Simple/Professional modes, configurable axes, LV0–LV6 weights, and the current algorithm;
- ten-level whole-number positive scores, five-level deductions, and exclusion of unrated axes;
- local image selection, resize/compression, preview, and PNG generation for all eleven ratios;
- merged axis score/reason entries, independent radar legend, and deterministic overflow gate;
- container-local drafts, templates, and preferences;
- JSBridge photo-album save;
- offline, bundle, compatibility, touch, accessibility, and recovery tests;
- accurate privacy, non-permanent-storage, and media-rights notices.

### 3.2 Explicitly excluded from the first release

- Accounts, cloud sync, telemetry, ads, remote logs, remote fonts, or arbitrary API requests;
- Tauri, desktop dialogs, Shell/process access, updater, and desktop recent files;
- arbitrary JSON open/save and browser-style download; the container picker is used only for supported images;
- Service Workers, Web Workers, WebAssembly, WebSocket, WebRTC, or background tasks;
- external links, new windows, clipboard, geolocation, notification, Bluetooth, USB, NFC, or other blocked capabilities;
- automatic or silent Xiaohongshu note publication;
- standalone PWA, Tauri Mobile, or Flutter apps, which belong to v0.4.0 technical validation.

### 3.3 Separate decision gate

`V03-DEC-01`: whether the first public release adds explicitly user-triggered `postNote`. The default is no: album save only. If later approved, it first requires a final confirmation screen, enforcement of the 20-character title / 1,000-character body / 1–18 media limits, cancellation, retry, privacy copy, and real-device acceptance. `postNote` must never be presented as a local export.

## 4. Container and ZIP contract

- The ZIP root directly contains the single `index.html` entry, with no wrapper directory.
- Allowed extensions are `.html`, `.css`, `.js`, `.png`, `.jpg`, `.jpeg`, `.gif`, `.webp`, `.svg`, `.woff`, `.woff2`, and `.json` only.
- Every resource uses a `./` relative path. External URLs, root-absolute paths, `<base>`, iframe, object, and a custom CSP meta tag are prohibited.
- JavaScript is external and classic. `type="module"`, `import`, `export`, inline scripts/events, `eval`, `new Function`, WASM, and Data/Blob/remote scripts are prohibited.
- The release ZIP excludes `node_modules`, `.git`, source maps, build configuration, test fixtures, and OS junk.
- The hard ZIP limit is 10 MiB and the project target is at most 2 MiB. Any text file over 2 MiB or total text over 5 MiB blocks promotion. A Base64 resource must decode to at most 1 MiB; anything over 100 KiB warns and should become a packaged file.
- Native capability calls use only exact `window.xhs.miniTool.*` APIs; custom `postMessage` bridges are prohibited.

## 5. Technical design

### 5.1 Reuse and boundaries

```text
Rating domain / Archive v2 / card view model
                  ↓
         MiniTool entry and UI
                  ↓
MiniToolPlatformServices contract
  ├─ local draft adapter
  ├─ image-picker adapter
  └─ XHS bridge adapter
       ├─ writeTempFile
       └─ saveImageToPhotosAlbum
```

The MiniTool entry must not import Tauri APIs. The platform contract exposes only narrow product capabilities; bridge parameters, error codes, and permission behavior stay in infrastructure. Browser, desktop, and MiniTool have separate builds while sharing pure domain logic and card fixtures.

### 5.2 Build design

M0 implements the following dedicated commands:

```text
npm run minitool:build   # produce dist-minitool/
npm run minitool:audit   # audit root, paths, extensions, blocked APIs, size, and script form
npm run minitool:pack    # zip only dist-minitool/ contents and emit SHA-256
npm run minitool:test    # MiniTool unit, component, and container-contract tests
npm run minitool:test:e2e # Chromium smoke tests against the final file:// artifact
```

- A dedicated Vite configuration uses `base: './'` and `target: ['es2017', 'chrome61']`.
- Final output is merged/transformed into classic IIFE JavaScript executable by Chrome 61; the default Vite ESM entry cannot remain.
- Source maps are disabled, and generated HTML, JS, and CSS are inspected rather than source alone.
- Tailwind, React, and `html-to-image` on Chrome 61 are an M0 high-risk probe; compilation alone is not compatibility evidence.
- If the existing DOM-to-PNG path fails under offline/container origin or old WebView, replace the MiniTool export adapter without changing the rating domain. Canvas 2D is an allowed fallback; WebGL is excluded.

### 5.3 JavaScript and CSS baseline

- The minimum Android verification baseline is Android 8.1 / Chrome-WebView 61. iOS follows the current platform floor and covers at least iOS 18.4+.
- Transpile ES2018+ syntax. New runtime APIs such as `replaceAll`, `at`, `Object.hasOwn`, and `structuredClone` require feature detection or a local fallback.
- Do not use UA sniffing, regex lookbehind, or Unicode property escapes.
- Flex and Grid are available, but `gap`, `aspect-ratio`, `min/max/clamp`, logical properties, `:focus-visible`, `dvh`, modern colors, and `backdrop-filter` require baseline fallbacks.
- The main region scrolls vertically with touch-friendly behavior. Critical actions are never hover-only; `visualViewport` is progressive enhancement for the soft keyboard.
- Apply normal padding first and then `env(safe-area-inset-*, 0px)`; set explicit `min-width: 0` / `min-height: 0` on Flex/Grid children.

## 6. Performance and resource budget

| Item                | Release target                                                 | Blocking condition                                               |
| ------------------- | -------------------------------------------------------------- | ---------------------------------------------------------------- |
| ZIP total           | ≤ 2 MiB                                                        | > 10 MiB                                                         |
| Initial HTML/CSS/JS | record static size for every file                              | unaudited or blocked resource present                            |
| User cover          | resize and prefer WebP; preview through Blob URL and revoke it | long-lived original-image Base64 causes material memory pressure |
| Card rendering      | DOM/Canvas 2D; generate once per save                          | core flow requires WASM/Worker/WebGL                             |
| Long lists          | paginate/window and render only necessary content              | unbounded eager rendering                                        |

Documentation distinguishes “static budget passed” from “real container runtime passed.” It must not claim smooth startup or low-memory stability before device measurement.

## 7. Data, privacy, and recovery

- Treat localStorage, sessionStorage, and IndexedDB as clearable container caches, not permanent storage.
- Debounce key saves. A write failure retains in-memory data, exposes an unsaved state, and still allows card export.
- v0.3.0 does not invent a false equivalent of desktop JSON backup; copy tells users to save completed cards to the album promptly.
- User images move only through memory, container storage, and explicitly saved album files. Do not request unrelated permission.
- If `postNote` is later enabled, the confirmation screen explains that selected text and images will be submitted to Xiaohongshu, and the call occurs only after the final explicit action.
- Crash recovery, corrupted-draft quarantine, quota failure, and bridge failure never overwrite usable current data.

## 11. Risks and mitigations

| Risk                                                     | Level  | Mitigation                                                                              |
| -------------------------------------------------------- | ------ | --------------------------------------------------------------------------------------- |
| Vite default ESM violates container rules                | High   | dedicated classic-IIFE pipeline and final HTML/JS audit                                 |
| Tailwind v4 emits CSS unsupported by Chrome 61           | High   | audit generated CSS in M0; baseline fallbacks and device fixtures                       |
| `html-to-image` fails in old/offline WebView             | High   | disprove early; replace MiniTool export adapter or use Canvas 2D                        |
| Container storage is cleared                             | High   | accurate non-permanent copy and save-state errors; never call it JSON-equivalent backup |
| Recent draft and content templates overwrite one another | High   | separate keys and validators, fixed startup precedence, and fail-without-write updates  |
| Large covers cause memory spikes                         | Medium | downsample, prefer WebP, revoke Blob URLs, low-end pressure test                        |
| JSBridge or permission differs by version                | Medium | feature detection, normalized errors, explicit gesture, recoverable retry               |
| Desktop capability leaks into ZIP                        | Medium | dedicated entry/dependency graph, blocked-API scan, final ZIP allowlist                 |

## 12. Suggested ownership

- Codex: platform boundary, classic-script build, bridge adapters, static audit, tests, and release evidence.
- Antigravity/Gemini: mobile UI polish within the compatibility and touch contract; no scoring, data, or bridge-permission changes.
- Human acceptance: real Xiaohongshu PC simulator and Android/iOS permission, save, screen-reader, and visual checks.

Any visual design that requires unsupported Chrome 61 CSS without fallback must be revised. Antigravity mockups do not substitute for real-container testing.
