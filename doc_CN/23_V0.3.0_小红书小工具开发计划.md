# V0.3.0 小红书小工具开发计划

状态：计划已定稿；M4 静态候选预检进行中，公开候选仍受源码冻结与多端实机门禁约束<br>
目标版本：`0.3.0`<br>
目标载体：小红书小工具离线 ZIP<br>
前置基线：Web v0.1 与 Windows v0.2 已冻结的评分领域、卡片模型和中英文文案

## 1. 版本定位

v0.3.0 是“小红书小工具版”，不是原生 Android/iOS 应用，也不是把桌面安装包直接移植到手机。原 v0.3 独立移动版计划整体顺延到 v0.4.0。

本版本保留“多维音乐评价 / `XDRate Music`”产品名，在发布说明中增加“小红书小工具版”载体标识。`com.xdrate.music`、`XDRate.Music` 等桌面/原生标识不用于小工具 ZIP；小工具包名和平台后台标识在接入官方发布流程时另行登记，不伪造 Android `applicationId`。

评分算法保持 `music-linear-100-v4`，综合分继续为 0–100 且保留一位小数；Archive Schema 保持 v2。平台适配不得改变评分结果、权重、未评分语义或 11 种卡片比例。

## 2. 核心用户闭环

1. 用户在小工具内填写作品信息、整数加分项、扣分项、理由与总体描述。
2. 草稿保存在当前小工具容器的本地存储中，并在重开时尽力恢复。
3. 用户预览与最终导出消费同一个卡片视图模型和布局计划。
4. 用户主动点击保存后，本地生成 PNG Data URI。
5. 平台适配器依次调用 `window.xhs.miniTool.writeTempFile` 和 `saveImageToPhotosAlbum`，经用户授权保存到系统相册。
6. 成功、取消、拒绝授权、空间不足和桥接不可用均提供明确反馈，不丢失当前编辑内容。

所有步骤默认不访问网络。保存到相册是用户明确触发的本地设备能力，不等同于上传或发布。

## 3. 范围

### 3.1 必须包含

- 简体中文和 English 编辑界面；
- 简易/专业模式、可配置分项、LV0–LV6 权重与现行评分算法；
- 10 级整数加分、5 级扣分、未评分不计分；
- 本地图片选择、裁切/压缩、预览与 11 种比例 PNG 生成；
- 分项理由与评分合并卡片、雷达图独立图例、确定性防溢出门禁；
- 容器本地草稿、模板及偏好恢复；
- JSBridge 相册保存；
- 离线、包体、兼容性、触控、无障碍与错误恢复测试；
- 清晰的隐私、存储非永久性及素材版权提示。

### 3.2 首版明确不包含

- 账号、云同步、遥测、广告、远程日志、远程字体或任意 API 请求；
- Tauri、桌面文件对话框、Shell、进程、系统更新器及桌面最近文件；
- 任意 JSON 文件打开、另存或浏览器式下载；容器文件选择仅用于受支持的图片媒体；
- Service Worker、Web Worker、WebAssembly、WebSocket、WebRTC 或后台任务；
- 外部链接、新窗口、剪贴板、定位、通知、蓝牙、USB、NFC 等容器禁用能力；
- 自动发布或静默发布小红书笔记；
- 独立 PWA、Tauri Mobile 或 Flutter 应用，这些属于 v0.4.0 的技术验证范围。

### 3.3 单独决策门槛

`V03-DEC-01`：首个公开版是否增加用户主动触发的 `postNote`。默认决策是“不包含”，仅保存到相册。若后续纳入，必须先完成发布前确认页、标题 20 字符/正文 1000 字符/媒体 1–18 项限制、用户取消路径、失败重试、隐私文案和真实设备验收；不得把 `postNote` 伪装成本地导出。

## 4. 容器与 ZIP 强制契约

- ZIP 根目录直接包含唯一入口 `index.html`，不得多包一层目录。
- 仅允许 `.html`、`.css`、`.js`、`.png`、`.jpg`、`.jpeg`、`.gif`、`.webp`、`.svg`、`.woff`、`.woff2`、`.json`。
- 所有资源使用 `./` 相对路径；禁止外部 URL、根绝对路径、`<base>`、iframe、object 和自定义 CSP meta。
- JavaScript 必须是外部经典脚本；禁止 `type="module"`、`import`、`export`、内联脚本、内联事件、`eval`、`new Function`、WASM、Data/Blob/远程脚本。
- 发布 ZIP 不得包含 `node_modules`、`.git`、源码映射、构建配置、测试夹具或系统垃圾文件。
- ZIP 硬上限 10 MiB，项目预算目标不超过 2 MiB；任一文本文件超过 2 MiB、文本总量超过 5 MiB 均阻止候选包晋级。单个 Base64 资源解码后不得超过 1 MiB，超过 100 KiB 即告警并优先改为包内文件。
- 原生能力只通过精确的 `window.xhs.miniTool.*` API 调用，禁止自造 `postMessage` 协议。

## 5. 技术方案

### 5.1 源码复用与边界

```text
评分领域 / Archive v2 / 卡片视图模型
                  ↓
         小工具应用入口与 UI
                  ↓
MiniToolPlatformServices contract
  ├─ local draft adapter
  ├─ image-picker adapter
  └─ XHS bridge adapter
       ├─ writeTempFile
       └─ saveImageToPhotosAlbum
```

小工具入口不得导入 Tauri API。平台契约只暴露业务需要的窄能力，桥接参数、错误码和授权细节留在基础设施层。浏览器、桌面与小工具各自构建，但共享纯领域逻辑和卡片渲染夹具。

### 5.2 构建方案

M0 已落地以下独立命令：

```text
npm run minitool:build   # 生成 dist-minitool/
npm run minitool:audit   # 静态审计入口、路径、扩展名、禁用 API、体积和脚本形态
npm run minitool:pack    # 仅打包 dist-minitool/ 内容并生成 SHA-256
npm run minitool:test    # 小工具单元、组件和容器契约测试
npm run minitool:test:e2e # 对最终 file:// 产物执行 Chromium 冒烟测试
```

- Vite 独立配置使用 `base: './'` 与 `target: ['es2017', 'chrome61']`。
- 最终产物必须合并/转换为 Chrome 61 可执行的经典 IIFE 脚本，不能保留 Vite 默认 ESM 入口。
- 禁用 source map，检查生成后的 HTML、JS 和 CSS，而不是只检查源码。
- Tailwind/React/`html-to-image` 是否能在 Chrome 61 容器稳定运行属于 M0 高风险探针；不能仅凭编译成功宣称兼容。
- 若现有 DOM 转 PNG 链在离线 `file`/容器环境或旧 WebView 失败，优先替换小工具导出适配器，不修改评分领域；Canvas 2D 是允许的回退，WebGL 不进入本版本。

### 5.3 JavaScript 与 CSS 兼容基线

- Android 最低验证基线为 Android 8.1 / Chrome-WebView 61；iOS 按小工具平台当前支持基线并至少覆盖 iOS 18.4+。
- ES2018+ 语法必须降级；`replaceAll`、`at`、`Object.hasOwn`、`structuredClone` 等新运行时 API 只能在能力检测后使用或提供本地回退。
- 不使用 UA 嗅探，不使用正则后行断言或 Unicode 属性转义。
- Flex/Grid 可用，但 `gap`、`aspect-ratio`、`min/max/clamp`、逻辑属性、`:focus-visible`、`dvh`、现代颜色与 `backdrop-filter` 必须有基础回退。
- 主滚动区使用触控友好的纵向滚动；关键按钮不得依赖 hover，软键盘通过 `visualViewport` 做渐进增强。
- 安全区先给普通 padding，再使用 `env(safe-area-inset-*, 0px)` 覆盖；所有 Flex/Grid 子项明确处理 `min-width: 0` / `min-height: 0`。

## 6. 性能与资源预算

| 项目             | 发布目标                                                | 阻塞条件                                |
| ---------------- | ------------------------------------------------------- | --------------------------------------- |
| ZIP 总大小       | ≤ 2 MiB                                                 | > 10 MiB                                |
| 初始 HTML/CSS/JS | 静态审计并记录各文件大小                                | 未审计或含禁用资源                      |
| 用户封面         | 选择后缩小尺寸并优先 WebP；预览使用 Blob URL 且及时释放 | 原图长期 Base64 驻留造成明显内存压力    |
| 卡片渲染         | DOM/Canvas 2D；保存时一次生成                           | 使用 WASM/Worker/WebGL 才能完成核心流程 |
| 长列表           | 分页或窗口化，单次只渲染可见/必要内容                   | 一次性渲染无界数据                      |

性能结论必须区分“静态预算通过”和“真实容器运行通过”。在实际设备测量前不得写“启动流畅”或“低内存稳定”等结论。

## 7. 数据、隐私与恢复

- localStorage、sessionStorage 或 IndexedDB 均视为可清理的容器本地缓存，不承诺永久保存。
- 每次关键编辑以防抖方式保存；写入失败必须保留内存数据、显示未保存状态并允许继续导出图片。
- v0.3.0 不提供桌面 JSON 文件备份的虚假等价物；文案明确建议用户及时把最终卡片保存到相册。
- 用户图片只在内存、容器存储和主动保存的相册文件之间流转；不得请求不相关权限。
- 若未来启用 `postNote`，确认页必须明确说明所选文本和图片将提交给小红书，并仅在用户最后一次明确操作后调用。
- 崩溃恢复、损坏草稿隔离、存储配额失败与桥接失败不得覆盖当前可用数据。

## 11. 风险与应对

| 风险                                      | 级别 | 应对                                                     |
| ----------------------------------------- | ---- | -------------------------------------------------------- |
| Vite 默认 ESM 不符合容器脚本规则          | 高   | 独立经典 IIFE 产线，并审计最终 HTML/JS                   |
| Tailwind v4 生成 Chrome 61 不支持的 CSS   | 高   | M0 审计最终 CSS，建立基础回退层和真实设备夹具            |
| `html-to-image` 在旧 WebView/离线环境失败 | 高   | M0 先证伪；必要时替换小工具导出适配器或用 Canvas 2D      |
| 容器存储被清理                            | 高   | 明确非永久性、保存状态与失败提示；不声称等价于 JSON 备份 |
| 最近草稿与内容模板相互覆盖                | 高   | 分离存储键、独立校验、固定启动优先级和失败不写入         |
| 大封面引起内存峰值                        | 中   | 选择后降采样、WebP、Blob URL 及时释放、低端机压力测试    |
| JSBridge 版本差异或授权拒绝               | 中   | 能力检测、统一错误、明确用户手势、可恢复重试             |
| 桌面能力误进入小工具包                    | 中   | 独立入口/依赖图、禁用 API 扫描和最终 ZIP 白名单          |

## 12. 分工建议

- Codex：平台边界、经典脚本构建、桥接适配器、静态审计、测试与发布证据。
- Antigravity/Gemini：在兼容基线和触控合同内优化移动 UI，不改评分算法、数据结构或桥接权限。
- 人工验收：真实小红书 PC 模拟器和 Android/iOS 设备授权、保存、读屏与视觉检查。

任何视觉方案若依赖 Chrome 61 不支持且无回退的 CSS，必须退回修改；不得以 Antigravity 效果图替代实际容器测试。
