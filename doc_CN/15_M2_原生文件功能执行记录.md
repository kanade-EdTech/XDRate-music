## 1. 交付结论

M2 原生文件纵向切片已落地：Windows 桌面版使用系统对话框打开/另存 XDRate 存档，并使用系统保存对话框导出 PNG；已关联存档可以直接保存。浏览器版仍保持下载式 JSON/PNG 与文件选择器导入，不依赖 Tauri。

本里程碑未修改 Archive Schema v2、评分领域模型或 `music-linear-100-v4`。桌面路径和原生句柄只存在于运行时工作区状态，不写入可移植存档。

## 2. 安全边界

- 前端未获得任意文件系统 API，也没有 shell、进程、HTTP 或 updater 权限。
- `allow-native-files` 只允许四个应用命令：打开存档、存档另存、关联存档保存、PNG 保存。
- 原生打开/另存的路径必须由用户在系统对话框中选择。
- 打开或另存成功后，Rust 端生成不可猜测的会话句柄；后续“保存”只提交句柄，不提交可修改的路径。句柄不会持久化，也不会进入 JSON。
- PNG 保存不产生可用于存档覆盖的关联句柄，避免文件类型能力混用。
- 存档最大 16 MiB；PNG 最大 64 MiB；Rust 端检查扩展名、UTF-8、Archive v2 外层结构和 PNG 签名，完整业务校验仍复用前端 Zod/迁移逻辑。

## 3. 写入与失败语义

存档和 PNG 都先在目标同目录创建唯一临时文件，完成写入并 `sync_all` 后再替换目标。Windows 使用 `MoveFileExW` 的 `REPLACE_EXISTING | WRITE_THROUGH`；替换失败会删除临时文件并保留原目标。

- 另存为取消：不创建文件，不改变关联路径或脏状态。
- 保存成功：更新关联路径/句柄，将“保存开始时的版本”记为最近成功保存版本。
- 保存过程中继续编辑：新编辑仍保持未保存，不会因旧快照落盘而误报“已保存”。
- 快速重复保存：前端同步锁与 Rust 同句柄写锁共同阻止并发写同一文件。
- 目标被移动或删除：返回 `target-missing`，不在旧路径静默重建；用户可使用“另存为”恢复。
- 只读、磁盘或替换失败：返回可恢复写入错误，当前编辑和原目标均保持。
- 系统保存对话框负责既有文件的覆盖确认；取消覆盖等同普通取消。

## 4. 用户界面

桌面运行时的“存档与模板”区域提供“保存存档”“打开存档”“存档另存为”，并显示当前关联路径和“已保存/有未保存更改”状态。无关联文件时，“保存存档”自动转入另存为。

PNG 继续复用同一预览 DOM、字体等待、2× 渲染和溢出门禁，仅最终二进制写入改由原生适配器处理。用户取消 PNG 保存不显示错误，也不产生文件。
