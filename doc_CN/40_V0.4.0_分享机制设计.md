# V0.4.0 分享机制设计

状态：设计稿；作为 v0.4.0 分享机制完善的产品与工程基线

## 1. 设计目标

分享机制不是“点一下就跳转”的单一按钮，而是一条可验证、可恢复、可解释的内容交付链路：用户先完成评分和卡片生成，再选择目标分享方式；系统在调用任何平台能力前保存可恢复草稿，并准确区分成功、取消、拒绝、失败和未知结果。

本版本只处理用户主动发起的分享，不后台上传、不代替用户完成公开发布、不读取平台账号数据，也不引入云端中转。

## 2. 用户可见的分享方式

| 方式 | 输入 | 输出 | 是否离开当前页面 | 失败后处理 |
| --- | --- | --- | --- | --- |
| 导出 PNG | 当前评分卡、比例、主题 | 本地 PNG 文件 | 否 | 保留编辑内容，可重试 |
| 保存相册 | PNG Data URI | 系统相册图片 | 可能 | 区分取消、拒绝、失败；保留预览 |
| 系统分享 | PNG/文本，由平台适配器决定 | 系统分享面板 | 可能 | 返回后恢复当前页面与草稿 |
| 小红书交接 | 确认页中的标题、正文、标签、评分卡图片 | 小红书原生发帖流程 | 是 | 标记已受理/取消/失败，不宣称已公开 |
| Toy/其他容器分享 | 容器允许的本地交接能力 | 容器原生流程 | 由容器决定 | 使用同一结果分类，不复制业务逻辑 |

平台不支持某种方式时，该入口应说明“不支持/未检测到”，但不能阻止其他本地方式继续工作。

### 2.1 目标平台清单与能力分级

产品目标可以保留为“希望一键到达这些平台”，但不能把缺少官方容器接口的平台写成已实现的直连发布。当前按能力分级：

| 容器 | 期望目标 | 当前可承诺能力 | 明确反驳/降级方案 |
| --- | --- | --- | --- |
| Bili Toy | QQ 空间、B 站动态、微信、贴吧、知乎 | Toy 内 PNG 导出、复制文本/链接、系统分享面板；若 Toy 平台提供明确的动态入口，再单独接入 | 当前 Toy CLI/容器没有上述第三方平台的统一发帖 API；`public`、`link-only` 或 Toy 发布不等于已同步到 QQ/微信/贴吧/知乎。缺少入口时统一降级为系统分享或手动粘贴 |
| 小红书小工具 | 小红书、QQ 空间、B 站动态、微信、微博 | 小红书仅在 Bridge 暴露 `postNote` 且能力探测通过时进入原生发帖流程；其余走系统分享、复制文本或导出图片 | 当前小工具 Bridge 只定义小红书发帖、临时文件、相册和打开小红书等窄能力，没有 QQ 空间、B 站动态、微信朋友圈/会话或微博直连接口；不得伪造“已发布” |
| 桌面/Web | 上述平台的分享入口 | PNG 文件、复制文字/链接，以及浏览器/操作系统可用的系统分享 | 平台客户端是否安装、是否接受预填内容由系统决定；失败时保留本地 PNG 和草稿 |

实现顺序固定为：相册保存（硬基线）→ 本地 PNG 导出 → 系统分享面板 → 平台专用 Bridge → 平台公开状态确认。后一级不可用时，前一级仍必须可用。

### 2.2 永远保留的基础能力：导出图片到相册

导出最终评分卡 PNG 到系统相册是所有版本、所有容器的最低能力，不因平台直连发布而被替代。相册入口必须使用最终预览同一份 PNG，用户主动触发，并区分完成、取消、权限拒绝和写入失败；失败时保留预览、草稿和重试入口。相册保存成功只表示图片已保存，不表示任何平台已发布。

### 2.3 可选个人签名档

在分享确认页提供“个人签名档（可选）”字段：

- 由用户自行填写短文本；为空时完全省略，不占卡片布局空间，也不参与评分。
- 允许出现在卡片页脚和分享文本中；预览、PNG、相册文件和平台交接使用同一个已确认值。
- 适配器不得自动追加账号、营销话题、位置、水印或平台文案。
- 清除草稿或重新生成卡片时，签名档按用户确认的本地草稿规则处理。

## 3. 标准用户流程

1. 用户编辑作品信息、评价轴、分数和文字。
2. 用户选择图片比例、主题及是否展示理由/故事。
3. 系统生成正式评分卡，并将预览与导出使用同一个渲染输入。
4. 用户选择导出、相册、系统分享或平台交接。
5. 若要离开当前页面，系统先保存当前评分草稿、卡片参数和待分享数据摘要。
6. 对会把文字或图片交给外部平台的方式，先展示确认页；用户必须明确点击最终操作。
7. 返回后恢复编辑状态、确认页内容和生成的 PNG；用户可继续编辑或重试。

## 4. 统一数据契约

### 4.1 ShareRequest

```ts
interface ShareRequest {
  requestId: string;
  createdAt: string;
  source: 'desktop' | 'web' | 'minitool' | 'toy' | 'wechat';
  card: {
    ratio: CardRatio;
    theme: CardTheme;
    pngDataUri: string;
    width: number;
    height: number;
    algorithm: 'music-linear-100-v4';
  };
  text?: {
    title?: string;
    content?: string;
    tags?: string;
    personalSignature?: string;
  };
  target:
    | 'file'
    | 'album'
    | 'system-share'
    | 'xiaohongshu-post'
    | 'bilibili-dynamic'
    | 'qq-zone'
    | 'wechat-share'
    | 'tieba'
    | 'zhihu'
    | 'weibo';
}
```

约束：PNG 必须是完整 `data:image/png;base64,...`，宽高来自最终渲染结果；文本只能来自用户当前确认页，不能在适配器中偷偷追加营销文案、话题或位置。

### 4.2 ShareResult

```ts
type ShareResult =
  | { status: 'completed'; requestId: string }
  | { status: 'accepted'; requestId: string }
  | { status: 'cancelled'; requestId: string; recoverable: true }
  | { status: 'denied'; requestId: string; recoverable: true; reason: string }
  | { status: 'failed'; requestId: string; recoverable: true; reason: string }
  | { status: 'unavailable'; requestId: string; recoverable: true; reason: string }
  | { status: 'unknown'; requestId: string; recoverable: true; reason: string };
```

`accepted` 只表示原生平台受理或已进入下一流程；只有 `completed` 才表示本地导出/相册操作完成。任何平台交接都不得把 `accepted` 文案写成“已发布”或“已公开”。

## 5. 状态机

```text
idle
 └─ prepare → preparing → ready
                         └─ invalid (可编辑修复)
ready ── confirm ──> confirming
confirming ── cancel ──> cancelled → ready
confirming ── submit ──> persisting
persisting ── save-failed ──> failed (禁止调用平台)
persisting ── saved ──> invoking
invoking ├─ completed ──> completed
         ├─ accepted ──> accepted
         ├─ cancelled ──> cancelled → ready
         ├─ denied ──> denied → ready
         ├─ failed ──> failed → ready
         └─ unavailable/unknown ──> corresponding result → ready
```

任何可恢复终态都必须保留：原评分草稿、卡片 PNG、比例、主题、确认页文字和上一次失败原因。重试必须是新的 `requestId`，不能在适配器内部无限自动重试。

## 6. 平台适配器边界

| 层 | 负责 | 不负责 |
| --- | --- | --- |
| 领域/评分核心 | 评分、综合分、领域数据 | 平台调用、文件权限 |
| 卡片渲染器 | 统一输入生成预览和 PNG | 分享面板、账号状态 |
| Share Orchestrator | 校验、持久化、状态机、结果归类 | 直接拼接平台私有参数 |
| Desktop Adapter | 文件保存、系统分享、窗口恢复 | 修改评分规则 |
| MiniTool Adapter | `writeTempFile`、相册、允许的 Bridge | 任意网络请求、后台发布 |
| Bili Toy Adapter | Toy 容器允许的本地交互 | 小红书 Bridge、B 站云能力 |
| WeChat Adapter（1.1.0） | 微信文件、相册、分享和生命周期 | 领域默认轴、评分算法 |

适配器只能实现窄接口。平台能力探测必须独立于业务校验；相册可用不代表发帖可用，系统分享可用也不代表目标平台已公开。

## 7. 隐私与安全边界

- 编辑阶段所有作品信息、评分、文字和封面只留在当前本地容器。
- 调用外部平台前，确认页必须说明将提交哪些文字和图片、提交给谁、最终公开动作由谁完成。
- 不保存账号 Cookie、平台返回令牌、帖子 ID 或未声明的设备标识。
- 生成 PNG 只使用本地资源；不加载远程图片、字体或分析脚本。
- 取消、拒绝和失败都不是数据删除操作；用户可以返回编辑并重试。
- 分享记录只保存最小恢复信息；用户清除草稿时一并清除待分享数据。

## 8. 失败分类与用户文案

| 分类 | 典型原因 | 用户动作 |
| --- | --- | --- |
| `invalid` | 图片无效、文本超限、缺少评分卡 | 返回编辑修复 |
| `unavailable` | 容器没有对应能力 | 改用 PNG/相册等本地方式 |
| `cancelled` | 用户关闭系统面板或原生页面 | 继续编辑或重试 |
| `denied` | 用户拒绝权限 | 到系统设置授权，或改用本地导出 |
| `failed` | 写文件、Bridge 或平台调用失败 | 查看原因并重试 |
| `unknown` | 页面离开或回调未返回 | 先恢复草稿，不重复自动提交 |

## 9. 验收矩阵

- 11 种比例：预览、PNG、相册和分享使用同一张图片，尺寸和文字一致。
- 文本：标题、正文、标签的字符限制在确认页实时可见，Unicode 截断不切断代理对。
- 持久化：调用前保存；取消、拒绝、失败、返回和刷新后内容完整恢复。
- 能力缺失：无 Bridge 时仍可编辑、预览、生成 PNG；不显示不可执行的成功按钮。
- 安全：构建产物无外部资源、网络请求、任意下载、账号读取和隐藏发布。
- 可访问性：键盘/触控目标不小于 44px，状态使用可读文本，焦点返回原操作位置。
- 设备：桌面、MiniTool、Toy 分别执行平台门禁；微信适配在 1.1.0 单独验收。

具体实施顺序、代码缺口和验收用例见 [V0.4.0 分享机制实现计划](./41_V0.4.0_分享机制实现计划.md)。

- v2.0.0 复用以上契约实现独立 App，不复制分享业务和评分算法。
