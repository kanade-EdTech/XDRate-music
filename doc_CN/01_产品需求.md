# 产品需求文档（PRD）

## 1. 背景与问题

现有音乐评分通常只给出单一数字，难以同时表达作品的艺术质量、听感、个人偏好、具体优缺点及听众与作品之间的故事。多维音乐评价（`XDRate Music`）用可配置的多维评分和可分享的可视化卡片解决这一问题，并确保所有数据默认只保存在用户设备上。

## 2. 产品目标

v0.1 必须做到：

1. 用户无需注册或联网即可完成一次音乐评价。
2. 用户可在简易模式和专业模式之间选择，并可修改、停用评价轴。
3. 系统根据维度分数和重要等级计算可解释的综合分。
4. 用户可补充评分理由、负面感受和个人故事。
5. 用户可生成、预览并下载清晰美观的评价图片。
6. 系统自动保存当前编辑内容，支持模板和完整存档的 JSON 导入/导出。

## 3. 非目标

v0.1 不包含：

- 用户账号、云同步、社区、点赞、评论或排行榜；
- 在线曲库、自动抓取专辑封面或版权素材；
- 服务端数据库、行为分析或广告；
- AI 自动评分或生成评价文本；
- 动漫、游戏、政治相关评价；
- 桌面安装包和移动原生应用。

## 4. 目标用户与场景

### 4.1 目标用户

- 希望结构化记录听歌体验的普通听众；
- 需要更细粒度维度的乐评爱好者；
- 希望制作可分享评分卡片的内容创作者；
- 重视隐私、希望离线保存评价的用户。

### 4.2 核心场景

1. 首次用户打开页面，填写歌曲与创作者，使用简易模式快速评分并下载图片。
2. 进阶用户切换专业模式，调整轴名和重要等级，填写每项理由并导出完整评价。
3. 常用用户保存一套自定义模板，以后创建新评价时复用。
4. 用户把完整存档导出为 JSON，在另一浏览器恢复或长期备份。

## 6. 功能需求

### FR-1 作品信息

- 必填：作品名。
- 选填：艺术家、专辑、最多 6 个自定义作品信息条目、发行年份、封面、标签。“艺术家”和“专辑”是可修改的本地化默认字段名；自定义条目由用户同时填写名称与内容。
- 封面必须由用户本地上传；不得提供未授权素材模板或在线抓取。
- 图片只在浏览器本地处理。实现应在保存前压缩，并校验类型与大小。

### FR-2 评分模式与评价轴

- 简易模式默认轴：艺术品质、听感、个人喜好。
- 专业模式默认轴：填词/立意、作曲/编曲、演唱/调音/混音、创新、其他。
- 每个轴包含名称、未评分或 1–10 分数、LV0–LV6 重要等级、启用状态、可选理由。
- 正向分数的唯一输入必须是 10 颗星：点击第 N 颗星得到整数 N，不显示或提供独立分数输入框，也不允许半星或其他小数星级。
- 默认等级为 LV3（×1.00），并作为用户偏好记住，用于下次新建评价。
- 至少保留一个启用且权重大于 0 的正向轴，才可计算综合分。

### FR-3 负面项

- 用户可启用一个或多个负面项，默认名称为“其他讨厌”。
- 分值范围为 -5–0；0 表示不扣分。
- 扣分的主要交互必须显示 5 个香蕉皮：填充数量表示扣分绝对值，旁边同时显示带负号的精确数值；小数扣分以最后一个香蕉皮的部分填充表示。
- 负面项在雷达图之外单独展示，避免不同量纲造成误导。

### FR-4 综合评分

- 系统按[功能规格](./02_功能规格.md)中的确定性公式计算结果。
- 综合总分必须完全使用 0–100 分制，并保留 1 位小数；界面和导出图片不得再并列显示十分制综合分。
- 单项评价轴使用 1–10 的整星整数；未评分轴不进入分子或权重分母。综合分仍使用未舍入的加权中间值，并按线性公式输出保留 1 位小数的百分制结果。
- 用户修改任何参与计算的值时，结果必须即时更新。
- UI 必须提供“查看计算方式”，不得把综合分表现为客观事实。

### FR-5 文本内容

- 所有文本均选填，包括各轴理由、负面原因、总体评价和个人故事。
- 系统不得把用户文本发送到网络。
- 导出卡片默认隐藏空白字段。

### FR-6 本地保存与模板

- 编辑状态发生变化后 500–1000 ms 防抖自动保存。
- 完整存档保存作品、评分、文本、样式与版本号。
- 模板只保存轴、权重和样式，不保存作品信息、封面或评价正文。
- JSON 导入前必须校验结构与版本；失败时不得覆盖当前数据。

### FR-7 图片导出

- 导出前提供与最终图片一致的预览。
- 必须支持 16:9、8:5、3:2、4:3、5:4、1:1、4:5、3:4、2:3、5:8、9:16 共 11 种比例。
- 预览与导出前必须完成字体加载和溢出检测；发现文字重叠或越界时禁止静默导出，并提示用户调整内容或版式。
- 默认导出 PNG，目标宽度 1200 px，支持 1×/2× 像素倍率。
- 文件名应清理非法字符，格式为 `作品名-XDRate-YYYYMMDD.png`。
- 导出失败时显示可操作的错误信息，并保留用户数据。

## 7. 非功能需求

| 类别     | 要求                                                                                   |
| -------- | -------------------------------------------------------------------------------------- |
| 隐私     | 无后端、无遥测、无第三方追踪；所有用户数据默认仅在本地。                               |
| 性能     | 常见桌面/移动设备首次可交互目标小于 3 秒；输入反馈小于 100 ms；普通卡片导出小于 5 秒。 |
| 兼容性   | 支持当前及前一个主版本的 Chrome、Edge、Firefox、Safari。                               |
| 响应式   | 360 px 宽度起可完成全部核心操作；桌面端优化预览与编辑双栏。                            |
| 无障碍   | 目标 WCAG 2.2 AA；键盘可操作、焦点可见、表单有名称、图表有文本替代。                   |
| 可维护性 | TypeScript 严格模式；计算与存储层具备单元测试；数据结构有版本与迁移。                  |
| 可靠性   | 自动保存失败必须告知用户；导入和升级不得静默丢失数据。                                 |

## 8. 成功指标

无遥测前提下，v0.1 以发布验收指标衡量：

- 关键流程端到端测试通过率 100%；
- 支持的浏览器中，创建、恢复、导入、导出成功率达到发布门槛；
- 全新用户在不阅读外部说明的情况下可在 5 分钟内生成首张卡片（人工可用性测试）；
- 严重级别 P0/P1 缺陷为 0；
- Lighthouse Accessibility 目标分数不低于 95（仅作为辅助指标）。
