## 1. 复核结论

Antigravity 完成了“存档与模板”区域的视觉整理、桌面响应式表现和新增文案。Codex 复核后接受 `V02-UI-01` 与 `V02-I18N-01` 的当前实现，但发现原交接证据不可复现且部分结论超出自动化实际覆盖范围，因此完成以下修订：

1. 未关联磁盘文件不再落入绿色“已保存到磁盘”分支；状态按“操作中 / 有未保存修改 / 已关联且已保存 / 未关联且尚未保存”区分。
2. 新增独立、可发现的 `npm run test:desktop-visual` 测试门；标准 Web E2E 继续保持 33 项，不再用其结果冒充桌面视觉测试结果。
3. 删除测试中指向 Antigravity 个人 `.gemini/antigravity/brain` 目录的绝对路径，所有截图仅写入工作区。
4. 125% 与 150% 自动化改为“有效 CSS 视口 + `deviceScaleFactor`”组合模拟，并生成完整页面截图；该测试是浏览器 DPR 模拟，不等同于真实 Windows 系统缩放、Tauri WebView、多显示器或读屏验收。
5. 后续由 Codex 使用项目内 M3 前固定基线补齐 `V02-UI-02`：专用用例以相同夹具生成关键页面、星星/香蕉皮和四个卡片比例族的逐项前后对比，覆盖深浅主题并生成 SHA-256 清单。
6. 真实 Windows 人工验收发现横向拖动无法触发布局变化。根因是原生窗口 `minWidth: 1120` 高于前端 1024 px 单栏断点；现改为 `minWidth: 720`，保留 `resizable: true`，并增加 1280 px 双栏切换到 960/720 px 单栏的自动化断言。

## 3. 自动化视觉证据

截图目录：`doc_CN/artifacts/desktop_handover/`

### 3.1 存档面板

- `panel-archive-browser-mode.png`：浏览器模式存档与模板面板；
- `panel-archive-desktop-unassociated.png`：桌面模式、尚未关联磁盘文件且存在未保存修改；
- 桌面用例断言“尚未关联文件”和“有未保存更改”可见，同时断言“已保存到磁盘”不存在。

面板截图使用最近的 `section` 祖先，不再误截取整个编辑器页面。

### 3.2 分辨率与 DPR 模拟

| 目标物理分辨率 / 模拟比例 |  CSS 视口 | `deviceScaleFactor` | 自动化结论                   |
| ------------------------- | --------: | ------------------: | ---------------------------- |
| 1920×1080 / 100%          | 1920×1080 |                 1.0 | 页面及可见交互控件无横向裁切 |
| 1600×900 / 100%           |  1600×900 |                 1.0 | 页面及可见交互控件无横向裁切 |
| 1366×768 / 100%           |  1366×768 |                 1.0 | 页面及可见交互控件无横向裁切 |
| 1280×720 / 100%           |  1280×720 |                 1.0 | 页面及可见交互控件无横向裁切 |
| 1280×720 / 125% 模拟      |  1024×576 |                1.25 | 页面及可见交互控件无横向裁切 |
| 1280×720 / 150% 模拟      |   853×480 |                 1.5 | 页面及可见交互控件无横向裁切 |

对应截图均为完整页面截图；另保留 1920×1080 的中英文、深浅主题证据。自动化只证明 DOM 横向边界与截图可生成，不单独证明不存在所有视觉重叠，也不能替代真实设备人工验收。

### 3.3 横向窗口调整

- 主窗口保持 `resizable: true`，最小宽度由 1120 px 降至 720 px；
- 自动化确认 1280 px 使用双栏，960 px 与 720 px 使用单栏；
- 三个宽度均无页面级横向溢出；720 px 完整页面证据为 `desktop-720x720-single-column-light-zh.png`；
- 用户已人工确认系统缩放变化后字体显示正常；新安装包仍需人工复验左右边缘拖动。
