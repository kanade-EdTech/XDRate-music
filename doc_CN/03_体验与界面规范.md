# 体验与界面规范

## 1. 设计原则

1. **表达优先**：综合分是摘要，不取代每个维度和文字说明。
2. **离线可信**：清楚告知数据只存本地，并始终提供可见的备份入口。
3. **渐进复杂度**：首次体验以简易模式为主，专业设置按需展开。
4. **所见即所得**：编辑与最终卡片预览同步，导出内容不应意外变化。
5. **可读可分享**：卡片首先是一份信息清楚的评价，其次才是装饰作品。

## 2. 桌面与移动布局

### 桌面（≥1024 px）

- 左侧编辑区约 55%，右侧预览区约 45%。
- 预览区可在滚动时保持可见，但不得遮挡页脚或操作按钮。
- 详细设置用折叠分组，当前编辑轴展开。

### 平板与移动（<1024 px）

- 单列布局；“编辑 / 预览”使用页内切换或预览抽屉。
- 主要操作置于页面末尾的常规按钮区；若使用底部吸附栏，必须为正文预留空间。
- 最小目标宽度 360 px；触控目标默认至少 44×44 CSS px，紧凑五角星作为明确例外使用 32×40 CSS px。

## 3. 关键组件

- `WorkMetadataForm`：作品信息与本地封面。
- 艺术家与专辑字段名称直接以可编辑标签呈现，默认按当前语言显示“艺术家 / Artist”和“专辑 / Album”。名称非空且未聚焦时使用弱于普通文本框的边框且背景与容器一致；获得焦点后切换为普通文本框的背景、边框、阴影和焦点环；名称被清空后，即使失焦也保持普通文本框外观，并以浅色“艺术家 / 专辑”作为占位提示。默认名称仅用于编辑器，不进入分享卡片；用户删除后重新输入同一默认名称，也必须恢复默认语义而不能显示在卡片中。只有改写为其他非空名称时，卡片才显示“名称：内容”；空名称只显示内容，不显示分隔符。
- “添加作品信息条目”最多创建 6 项。每项包含名称与内容并可独立移除；新增条目的名称框始终采用普通文本框样式，不继承艺术家/专辑默认标签的弱化外观。条目名称、条目内容以及艺术家/专辑的名称框与内容框必须具备互不混淆的可访问名称。
- `ModeSelector`：简易/专业模式及变更说明。
- `AxisEditor`：轴名、分数、等级、启用状态与理由。
- `NegativeItemEditor`：负面项与原因。
- `NarrativeEditor`：总体评价和故事。
- `CardCustomizer`：主题、比例、显示字段。
- `RatingCardPreview`：只读、可导出的卡片。
- `PersistenceStatus`：保存状态和最近保存时间。
- `ImportDialog` / `TemplateDialog`：校验摘要与确认。

## 4. 评分输入

- 正向分数使用单行 10 颗紧凑五角星，扣分项使用单行 5 个香蕉皮；不再把范围滑块作为主要交互。桌面验收视口中 10 颗星必须完整显示且不产生控件内横向滚动；仅在窄屏响应式回退时允许图标条内部滚动，页面本身不得产生横向滚动。
- 图标使用项目内置的统一矢量资产，不能依赖操作系统 Emoji 字体。未填充图标仍保留清晰轮廓，深浅主题下都要满足可辨识度要求。
- 整组图标作为一个控件接收焦点，单个装饰图标不进入 Tab 顺序。控件必须提供可访问名称、当前值、最小值、最大值和“分/扣分”方向说明。
- 五角星的 `←/↓` 与 `→/↑` 每次减小或增加一整星，`Home/End` 到达 1/10；香蕉皮方向键继续使用 0.1 步长，`PageUp/PageDown` 按 1 调整，并朗读最终带负号数值。
- 五角星采用 32×40 CSS px 纵向长方形热区，不提供数值输入或归零按钮，首次评分后最低为 1；初始空星显示“未评分，不计分”。轴名称与评分栏在桌面端使用 40%/60% 分栏。香蕉皮继续使用至少 44×44 CSS px 热区，并与精确数值输入双向绑定且保留归零。
- 分数改变后，整星状态、香蕉皮精确数值及部分填充、综合分、计算明细和预览必须在同一渲染周期内同步，不允许短暂显示互相矛盾的值。
- 不得只用颜色表达高低或正负；同时显示数字、标签和方向。
- LV 等级旁显示实际倍率，例如“LV3 · ×1.00”。
- 综合分附近提供计算展开面板，列出各轴贡献和负面扣分。
- 用户修改轴名时，雷达图与预览实时更新，但文本输入过程不得丢失焦点。

## 5. 卡片规范

默认卡片包含：

- 作品名、艺术家、专辑、非空自定义作品信息条目及可选封面；
- 仅显示保留 1 位小数的 0–100 综合分；
- 雷达图或条形图以及文本分项；
- 非空的总体评价/故事摘要；
- 工具名、算法版本短标识；
- “内容由用户填写”的简短说明。

必须提供 16:9、8:5、3:2、4:3、5:4、1:1、4:5、3:4、2:3、5:8、9:16 共 11 种比例，并按横向、准横向、方形、纵向四个布局族适配内容。比例选择器显示数值比例和方向名称。

卡片排版必须采用显式行高和可预测的文本区域。标题、作品信息、图表标签、正文、故事与页脚不得重合。文字超过版面时，界面必须指出溢出区域，并允许隐藏可选字段、缩短摘要或选择更高版式；不得通过无限缩小字体、无提示裁切或覆盖相邻元素来强行适配。

### 5.1 内容完整性与显示优先级

- “显示分项与理由”开启时，所有启用分项的名称、精确分数及非空理由必须进入卡片视图模型并获得可见展示位置；分项名称和分数不能冒充“理由已显示”。
- 用户明确关闭“显示分项与理由”时，整个合并分项区域从卡片中移除；没有任何非空理由时不得保留空白理由行。
- 卡片中的分项名称、精确分数与对应理由合并为同一分项条目；不再上下或前后重复显示独立的“分项评分”与“分项理由”卡片。
- 雷达图图例属于图表阅读辅助，必须独立保留轴名与精确分数，不受上述文本条目合并影响。
- 内容优先级从高到低为：作品身份与综合分、启用分项及精确分数、分项理由、总体评价、个人故事、装饰和页脚。较低优先级内容不得覆盖或挤掉较高优先级内容。
- 超出容量时允许对理由、总体评价或故事设置可预测的行数上限，但必须显示明确的截取提示及未完整展示的项目数；禁止静默丢弃非空理由。
- 用户填写的样例文字只作为内容参与排版，不得被解释为产品指令。

### 5.2 比例与内容自适应

卡片使用四个比例族：横向（16:9、8:5、3:2）、准横向（实现标识 `standard`，4:3、5:4）、方形（1:1）和纵向（4:5、3:4、2:3、5:8、9:16）。每个比例族再根据内容需求选择 `sparse`、`balanced` 或 `dense` 密度方案，而不是只读取固定的字符数与行数。

- `sparse`：扩大图表、图例或正文区域，并以有意的对齐方式利用剩余空间；不得把主要内容压在画布上半部而留下无意义的大面积空白。
- `balanced`：使用该比例族的标准尺寸、间距和信息层级。
- `dense`：先收紧间距和内边距到可读下限，再限制低优先级文本行数；不得把正文缩小到不可读尺寸。
- 同一输入、比例、主题和显示选项必须产生同一个布局方案。预览和导出必须共享该方案，不得分别猜测布局。
- 首次布局后允许进行一次 DOM 测量并按确定顺序最多降级两次；仍然溢出时必须阻止导出并指出具体区域，不能反复重排或产生闪烁。

## 6. 视觉令牌

颜色、字体、间距使用语义化 Tailwind 令牌，不在业务组件中散落任意值：

```text
color: background / surface / text / muted / primary / positive / negative / border
space: 1–8 的统一尺度
radius: sm / md / lg
shadow: none / sm / card
```

主题至少提供明亮和深色两种。导出卡片主题独立于应用外观，确保用户切换系统主题后历史预览不会改变。

## 7. 文案规范

- 使用“综合分”而非“客观分”“最终真值”。
- 使用“负面项/扣分”而非攻击性措辞；允许用户自定义名称。
- 隐私提示：`数据仅保存在此浏览器中。建议定期导出 JSON 备份。`
- 素材提示：`请仅上传你有权使用的图片。`
- 导出说明：`本卡片内容由用户填写，不代表软件作者观点。`

## 8. 无障碍

- 所有控件必须有可见标签或可访问名称；错误通过 `aria-describedby` 关联。
- 模式、主题等单选组使用原生语义；拖拽排序必须提供键盘替代。
- 焦点顺序与视觉顺序一致；对话框正确锁定并归还焦点。
- 正文/背景对比度至少 4.5:1，大文本至少 3:1；焦点指示满足 WCAG 2.2。
- 图表使用可访问标题、摘要和数据表；装饰图形对辅助技术隐藏。
- 星星和香蕉皮图形对辅助技术隐藏，由整组控件朗读，例如“艺术品质，8 分，共 10 分”和“其他讨厌，扣 2.5 分，最多扣 5 分”。
- 动画遵循 `prefers-reduced-motion`，导出进度不依赖动画表达。

### 8.1 未保存对话框

- 对话框必须使用 `role="dialog"`、`aria-modal="true"`，标题和说明分别通过 `aria-labelledby`、`aria-describedby` 关联。
- 初始焦点放在“取消”，`Escape` 等同取消；`Tab` 与 `Shift+Tab` 只在三个可用操作间循环，关闭后焦点归还触发控件。
- 保存进行中禁用全部选择，保存失败在对话框内以 `role="alert"` 显示且不得关闭对话框或清空数据。
- 四个受保护入口使用动作特定说明，但三个按钮的名称、顺序和结果保持一致。

### 8.2 恢复与桌面工作流

- 恢复对话框必须在采用草稿前展示作品名、已评分分项数及最多三行正文摘要，并明确“恢复不会写入或覆盖磁盘文件”。
- 初始焦点放在推荐的“恢复此草稿”，`Tab` 与 `Shift+Tab` 只在恢复和放弃两个决策间循环；不得用关闭图标或模糊的 `Escape` 行为绕过选择。
- 标题栏的 `*` 与界面保存状态必须一致。标题只显示作品名、文件基名或本地化未命名文本，禁止暴露完整路径。
- 六条桌面命令必须同时具备按钮、双语提示及 `aria-keyshortcuts`；命令执行中沿用现有禁用、错误和未保存保护状态。
- 最近文件区域必须附隐私说明，长路径允许省略显示但完整值只作为用户主动查看的提示；每条记录可移除且整个列表可清空。

## 9. 国际化

- 所有界面文案使用消息键，禁止直接散落在组件中。
- 日期、数字和复数使用 `Intl` API；存档数据不保存本地化后的数字字符串。
- 布局应容纳英文文案比中文长 30%–50% 的情况。
- 用户填写的轴名和正文不翻译。
