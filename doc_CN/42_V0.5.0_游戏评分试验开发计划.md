# V0.5.0 游戏评分试验开发计划

状态：规划基线；承接 v0.4.0 分享机制，不启动独立 App

日期：2026-09-25

## 1. 目标

0.5.0 用最小的游戏领域试验验证“领域包 + 通用评分引擎 + 评分卡 + 分享链路”是否成立。它不是游戏数据库，也不是一次性重做前端；音乐主线、Archive Schema、PNG 导出和已验证的分享状态机继续复用。

本版本特别验证一组带封面的个人评价模板：用户打开游戏评分入口即可看到少量作者示例，并能将其作为起点继续编辑。示例必须被理解为个人观点和工程夹具，不得伪装成官方评分、榜单或客观推荐。

## 2. 产品边界

### 必须交付

- 独立的游戏领域包和入口，不覆盖音乐入口。
- 游戏作品字段：名称、平台、版本/发行信息、封面和可选备注。
- 游戏默认评价轴、理由、可选扣分项和综合分规则；评分引擎仍使用共享契约。
- 3–5 个带封面的“示例模板 / 个人评价”。每个模板包含分数、理由、总体评价和可复制的模板结构。
- 模板支持套用、复制为新模板、改名和删除；用户编辑不能回写内置示例。
- 预览、PNG、相册、签名档和分享确认页继续使用 v0.4.x 的同源快照。
- 中英文文案、窄屏触控、键盘、空状态和本地草稿恢复。
- 游戏领域的 Archive Schema 迁移、导入/导出和回归夹具。

### 明确不做

- 不接入游戏数据库、联网资料、排行榜、评论区或账号系统。
- 不把个人模板包装成“官方推荐”或平台公共内容。
- 不把未获授权的商业封面打进公开 Toy、MiniTool 或正式发布包。
- 不复制一套游戏专用评分引擎，不修改音乐 v0.3.x 的历史结果。
- 不实现 Android/iOS 独立 App；该事项仍属于 2.0.0。

## 3. 个人评价模板设计

### 3.1 模板来源

模板分为两类：

| 来源 | 含义 | 是否可删除 | 是否允许覆盖 |
| --- | --- | --- | --- |
| `seeded-example` | 项目随试验版提供的作者个人示例 | 是 | 否，套用后复制为用户模板 |
| `user-created` | 用户从示例或空白入口创建的模板 | 是 | 是 |

每个模板保存稳定 ID、显示名称、来源、创建时间、修改时间和内容快照。内置模板即使被用户改名，也不能通过同 ID 写回种子数据。

### 3.2 展示与文案

- 模板卡片必须显示“示例模板 / 个人评价”标识。
- 评分旁边显示评价者身份为“作者个人记录”，不显示“推荐”“最佳”或排名语义。
- 封面旁提供来源/授权说明入口；没有明确授权的素材只允许本地探针使用。
- 一键清除只清除当前作品内容，不删除模板库。
- 空白状态说明评分、理由和灰色占位文字不会被当作真实评价。

### 3.3 首批模板覆盖目标

首批 3–5 个模板不追求数量，重点覆盖：长标题、不同平台字段、版本差异、长理由、极端分数分布、横竖不同封面和无封面回退。模板具体作品名单由用户在实现前确认，避免把示例内容误认为产品立场。

## 4. 数据与领域契约

建议新增声明式领域包，而不是在组件中写死游戏分支：

```ts
interface GameTemplateDefinition {
  id: string;
  source: 'seeded-example' | 'user-created';
  title: string;
  cover?: LocalCoverRef;
  work: { platform?: string; version?: string; releaseNote?: string };
  axes: RatingAxis[];
  deductions: Deduction[];
  narrative?: string;
  personalSignature?: string;
  attribution?: { label: string; usage: 'cleared' | 'local-only' | 'unknown' };
}
```

实现约束：

1. `source`、`id` 和 `attribution` 进入模板存档，便于审计和迁移。
2. `source: seeded-example` 的内容只能通过“套用/复制”进入编辑态。
3. 评分规则、卡片布局和分享编排器依赖通用接口，不依赖具体游戏名称。
4. 导出 JSON 时保留领域标识和算法版本；导入旧音乐存档不得被误判为游戏存档。

## 5. 阶段计划

| 阶段 | 工作包 | 主要产物 | 完成门槛 |
| --- | --- | --- | --- |
| M0 | 领域契约与样例清单 | `GameDomainDefinition`、字段表、模板来源/版权清单 | 领域包不污染音乐默认值；样例素材有处理结论 |
| M1 | 模板库与编辑行为 | 种子模板、套用/复制/改名/删除、清除隔离 | 修改用户副本不会改变种子模板；刷新可恢复 |
| M2 | 评分与卡片 | 游戏默认轴、理由/扣分、11 比例卡片和签名档 | 预览、PNG、相册和分享使用同一快照 |
| M3 | 导入导出与兼容 | Schema 迁移、JSON 夹具、错误提示 | 音乐旧档可读；游戏档可识别；损坏档不覆盖当前内容 |
| M4 | 验收与试验包 | 单测、E2E、视觉矩阵、Toy/MiniTool 试验包 | 无溢出、无外链、无版权越界；个人评价标识完整 |

## 6. 测试矩阵

- 模板：首次种子、套用、复制、改名、删除、清除后模板仍在、刷新恢复。
- 数据隔离：用户修改、导出、导入和删除均不改变 `seeded-example` 原始快照。
- 评分：未评分轴、满分、低分、扣分项、长理由和空理由。
- 卡片：11 种比例、横竖封面、无封面、长标题、平台/版本字段、签名档为空/非空。
- 兼容：音乐 Schema v2、游戏领域存档、未知领域版本和损坏 JSON。
- 安全：无远程封面、无账号读取、无第三方网络请求、公开包只含已确认素材。
- 可访问性：模板操作有可读名称，删除/清除有确认，触控目标不小于 44px，键盘焦点可恢复。

## 7. 交付与退出条件

交付物：

1. 中英文游戏领域定义与模板数据说明。
2. 可删除、可复制的示例模板库。
3. 游戏领域单测、E2E、视觉和迁移夹具。
4. 试验包、文件清单、SHA-256 和已知限制。
5. 一份明确写出“个人评价，不代表官方结论”的发布说明。

退出条件：

- 游戏领域可以独立启用/关闭，音乐主线结果不变。
- 示例模板与用户内容完全隔离，删除和改名行为可恢复、可验证。
- 11 种比例和分享链路不出现新的快照失效或布局溢出。
- 每张公开使用的封面都有明确来源结论。
- 领域契约和证据通过后，才进入 1.0.0 动漫独立试验；不因模板数量不足而扩展成游戏数据库。

## 8. 推荐分支与顺序

```text
codex/v0.5.0-game-rating
  ├─ M0 领域契约与素材清单
  ├─ M1 模板库与隔离
  ├─ M2 评分卡与分享复用
  ├─ M3 存档迁移
  └─ M4 试验包与验收
```

建议先做 M0 和 M1，再决定具体模板作品名单；不要先收集大量封面后再补版权和数据隔离规则。
