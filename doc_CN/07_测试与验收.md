# 测试与验收规范

## 1. 测试分层

| 层级     | 工具                    | 覆盖重点                           |
| -------- | ----------------------- | ---------------------------------- |
| 单元测试 | Vitest                  | 评分、校验、迁移、文件名、视图模型 |
| 组件测试 | Testing Library         | 表单联动、模式切换、错误与键盘行为 |
| 端到端   | Playwright              | 核心流程、存档恢复、导入、PNG 导出 |
| 视觉检查 | Playwright 截图 + 人工  | 卡片比例、主题、长文本、中英文     |
| 无障碍   | axe + 键盘/读屏人工检查 | WCAG 2.2 AA 核心问题               |

自动化结果不能替代真实浏览器中的下载文件检查、键盘检查和至少一次读屏冒烟测试。

## 2. 评分算法用例

- 所有轴同分时，综合正向分等于该分值。
- LV0 轴不参与分母和分子，但可显示。
- 停用轴既不计算也不显示。
- 未评分轴既不参与分子和权重分母，也不出现在卡片图表；一个已评分轴不得被高权重未评分轴稀释。
- 不同权重按规格表正确换算。
- 多个负面项按每 -1 等于 -10 分线性累加；结果限制在 0–100。
- 所有参与轴均为 LV0 时返回不可计算状态，不出现 `NaN`。
- 计算使用原始精度，只在展示时舍入。
- `score100` 由未舍入的百分制中间值四舍五入到 1 位小数。

建议对合法范围做属性测试：结果始终为有限数且位于 0–100，增加负面扣分不会提高结果；任一轴增加固定值时，其综合分增量与该轴归一化权重呈线性关系。

## 2.1 图标评分控件用例

- 未评分以及整数 1、5、10 分分别得到正确的空星、整星和满星状态；正向区域不存在数值输入或部分填充，并正确显示“未评分，不计分”。
- 0、-0.1、-2.5、-4.9、-5.0 分分别得到正确的香蕉皮填充状态；填充越多只会让存储值更负。
- 点击第 N 颗星得到整数 N，方向键按一整星移动，Home 定位到 1，且不存在正向数值输入或归零按钮。香蕉皮继续支持 0.1 数值输入，并可归零到 0。
- 图标、数字、计算结果和预览在一次输入后保持同步；刷新、导入和模板初始化后也必须一致。
- 整组控件只有一个 Tab 停靠点，读屏能朗读名称、当前值、范围和扣分方向；不读取十个“星星按钮”或五个“香蕉皮按钮”。
- 深浅主题、360 px 视口、200% 浏览器缩放和触控下，图标不得重叠或截断；星星目标固定为 32×40 CSS px（高宽比 1.25），香蕉皮至少 44×44 CSS px。1280 px 及以上桌面验收视口断言十星条 `scrollWidth <= clientWidth`。

## 2.2 卡片编排算法用例

- 相同草稿、显示选项、比例和主题必须生成完全相同的 `CardContentProfile` 与 `CardLayoutPlan`。
- CJK、全角、英文、数字和混合文本按规定文本单位计算，并在固定有效行宽下得到确定的预计行数。
- 11 种比例分别覆盖空内容、稀疏、常规、密集和极限五类夹具；密度边界值 `0.65` 与 `0.95` 的分档必须有单元测试。
- `showReasons=true` 时，所有已评分且启用分项的非空理由进入视图模型，并与名称和精确分数显示在同一分项条目；未评分分项不进入评分卡。`showReasons=false` 或理由全空时，同一条目只显示名称和分数且不生成空理由行。雷达图图例在两种状态下均保留。
- 稀疏内容不会只堆积在画布上半部；密集内容按固定顺序进入最多两次降级，不能产生来回振荡。
- DOM 测量只能确认实际溢出并触发确定性降级，不能改变评分、存档或用户文本。
- 预览和导出使用同一个布局计划；最终仍溢出时返回具体区域并禁止导出。

## 3. 核心验收场景

### AC-01 首次评分

**前置**：无本地数据。  
**操作**：填写作品名，保留简易模式默认三轴并评分。  
**结果**：即时显示保留 1 位小数的正确百分制综合分和图表；不显示十分制综合分，且无网络请求。

### AC-02 自定义专业评分

**操作**：切换专业模式，重命名轴、停用一轴、修改等级并填写理由。  
**结果**：计算只使用已评分、启用且非 LV0 的轴，预览同步反映名称、分数和文本。

### AC-03 负面扣分

**操作**：增加 -1.5 的负面项。  
**结果**：百分制综合分减少 15.0，雷达图不含负分轴，明细明确显示扣分。

### AC-03A 星星与香蕉皮输入

**操作**：点击第 8 颗星，再用键盘减小 1 星并恢复；点击第 3 个香蕉皮，再用键盘减少扣分 0.5。  
**结果**：正向分为 8 颗完整星且没有独立数值输入；扣分显示 -2.5、两个满香蕉皮和一个半填充香蕉皮；综合分仍保留 1 位小数，并与自动保存和预览同步更新。

### AC-04 自动恢复

**操作**：编辑后等待保存，刷新页面。  
**结果**：可继续上次内容，作品、分数、文本、样式和封面一致；显示最近保存状态。

- 艺术家与专辑名称初始显示本地化默认值，静止态为透明背景与弱边框，聚焦态切换为普通文本框；清空后显示浅色默认名称占位符。默认名称、清空名称及清空后重新输入的同一默认名称均不进入卡片，卡片只显示内容；改为其他非空名称后才显示“名称：内容”。
- 添加自定义作品信息条目后，名称框始终采用普通文本框；名称、内容、删除操作、卡片显示、刷新恢复及 JSON 往返保持一致。
- 导入缺少扩展作品信息字段的旧 v2 存档时，补 `artistLabel: null`、`albumLabel: null` 与 `extraFields: []`，不得拒绝或丢失原有内容。

### AC-05 安全导入

**操作**：依次导入合法 v1、损坏 JSON、未知高版本和超限文件。  
**结果**：合法文件预览后导入；其余给出明确错误，当前草稿不变。

### AC-06 模板隔离

**操作**：从含作品和正文的评价保存模板，再用于新评价。  
**结果**：只带入轴、等级和样式，不泄露作品信息、封面、分数或正文。

### AC-07 PNG 导出

**操作**：分别以 11 种比例、明暗主题和 1×/2× 导出，并覆盖中英文、长标题、最大轴数和长正文夹具。  
**结果**：文件名合法，图片可打开，内容与预览一致；字体、标题、图表标签、正文和页脚无重合、越界、交互控件或静默裁切。

### AC-07A 溢出保护

**操作**：在最矮的 16:9 卡片中输入超长标题、轴名、正文和故事。  
**结果**：系统指出具体溢出区域并禁止导出，直到用户隐藏可选字段、缩短内容或更换比例；不得仅靠缩小字体掩盖问题。

### AC-07B 描述与内容自适应

**操作**：在 1:1 夹具中为三个启用分项填写理由，分别导出理由开启/关闭版本；再以同一数据验证代表性的横向、标准和纵向比例，并依次替换为空、稀疏、常规、密集和极限文本。  
**结果**：“显示分项与理由”开启时，每个分项在同一条目中显示名称、精确分数和非空理由，或带有明确的未完整展示数量；关闭时整个合并分项区域移除；雷达图图例始终保留轴名和精确分数。布局按内容密度确定性调整，稀疏内容无无意义的大面积下部空白，密集内容无重合或静默裁切，预览与 PNG 一致。

### AC-08 存储失败

**操作**：模拟存储不可用或配额满。  
**结果**：当前输入仍在内存中；界面提示保存失败并提供 JSON 导出，不宣称已保存。

### AC-09 键盘与读屏

**操作**：仅用键盘完成作品输入、评分、预览和导出。  
**结果**：焦点可见、顺序合理、对话框归还焦点、分数变化与错误被辅助技术感知。

### AC-10 未保存修改保护

**操作**：让工作区产生未保存修改，分别从新建、打开其他存档、关闭窗口和退出应用进入保护流程；每个入口依次选择保存并继续、放弃修改和取消，并补测保存对话框取消与保存失败。  
**结果**：保存成功后才继续；放弃不写盘但继续；取消、保存取消和保存失败均保留当前窗口、数据与脏状态。桌面对话框焦点受限且可用 `Escape` 取消，浏览器刷新/关闭触发原生离页警告。

### AC-11 窗口标题与保存状态

**操作**：依次验证新建、打开、编辑、保存成功、保存取消和保存失败。  
**结果**：标题优先显示作品名，作品名为空时显示文件基名或本地化“未命名评价”；未保存时带 `*`，仅保存成功后移除；标题不出现完整本地路径。

### AC-12 桌面命令与快捷键

**操作**：在中英文界面、普通页面及文本框聚焦状态下验证 `Ctrl+N/O/S/Shift+S/Shift+E/Q`。  
**结果**：六条命令分别执行新建、打开、保存、另存、PNG 和退出；所有命令有可见按钮与双语提示；复制、粘贴、剪切、撤销、重做、全选和普通输入不受影响；取消受保护命令后文字与焦点保留。

### AC-13 最近文件

**操作**：打开或保存多个存档，重复使用大小写或斜杠形式不同的同一路径，制造超过 10 条记录并移动一个磁盘文件。  
**结果**：列表按最新使用排序、路径去重且最多 10 条；失效记录只在用户要求时移除；可清空列表；界面明确说明仅保留本机元数据且不会自动打开或扫描目录。

### AC-14 异常恢复

**操作**：编辑并等待自动草稿后模拟异常退出，再启动应用，分别验证恢复和放弃。  
**结果**：应用先显示作品名、已评分分项数和正文摘要；恢复决定前不让空白初始状态覆盖草稿；恢复仅载入编辑区且不写盘，放弃后不再提示；对话框初始焦点明确并限制在决策控件内。

## 4. 兼容性矩阵

当前桌面版本发布前至少验证：

- Windows：Chrome、Edge、Firefox 当前稳定版；
- macOS：Safari 当前稳定版、Chrome；
- 1280×720、1440×900、1920×1080 代表性桌面视口；
- 鼠标和键盘输入；100%、125%、150% 系统缩放及 1×/高 DPI 屏幕。

360–430 px 响应式视口可继续保留自动化回归，但真实 iOS Safari、Android Chrome 与移动触控验收后移至 v0.3，不作为当前桌面版本或 V0.2 桌面版的发布阻塞项。

## 5. 性能与容量

- 使用 12 个正向轴、5 个负面项、各字段最大文本和 3 MB 封面做压力样例。
- 连续编辑 10 分钟不得明显卡顿或无限增长内存。
- 导出按钮应防止重复提交，操作超过 1 秒显示进度。
- 存档接近上限时导入、恢复和导出必须保持可预期，失败不得丢数据。

## 6. 发布门槛

- 必需 CI 检查全部通过；
- P0/P1 已知缺陷为 0；P2 缺陷有记录和规避方式；
- 核心端到端场景在目标浏览器通过；
- 无严重/高危依赖漏洞，或已有书面风险接受与替代计划；
- axe 核心页面无 serious/critical 问题；
- 隐私检查确认没有意外网络请求、遥测或远程字体；
- 中英文 UI 及存档往返测试通过；
- LICENSE、免责声明、版本、Schema 和算法版本一致。
