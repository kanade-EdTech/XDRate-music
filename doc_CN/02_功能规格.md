# 功能规格

## 1. 主流程

`新建/恢复草稿 → 填写作品信息 → 选择模式/模板 → 评分与写评语 → 预览 → 下载 PNG / 导出 JSON`

应用启动时先检查本地草稿。若草稿存在，显示“继续上次编辑”和“新建评价”；新建操作需二次确认，或先提供导出备份入口。

## 2. 页面与状态

v0.1 推荐单页分区实现：

1. 顶栏：项目名、语言、导入、导出、帮助。
2. 作品信息：标题、可自定义名称的艺术家与专辑字段、最多 6 个自定义条目、年份、封面、标签。
3. 评分设置：模式、模板、评价轴与重要等级。
4. 详细评价：理由、负面项、总体评价、故事。
5. 卡片设置：主题、尺寸、显示项。
6. 实时预览：雷达图、综合分、文本与免责声明短句。
7. 操作区：下载图片、保存模板、重置。

应用必须区分以下状态：`clean`、`dirty`、`saving`、`saved`、`save-error`、`exporting`、`export-error`。

## 3. 字段约束

| 字段            | 类型         | 约束                                    | 默认值   |
| --------------- | ------------ | --------------------------------------- | -------- |
| 作品名          | string       | 必填，1–120 字符                        | 空       |
| 艺术家/专辑内容 | string       | 0–120 字符                              | 空       |
| 艺术家/专辑名称 | string/null  | 0–24 字符；`null` 使用本地化默认名      | `null`   |
| 自定义条目      | object[]     | 最多 6 项；名称 0–24、内容 0–120 字符   | `[]`     |
| 发行年份        | integer/null | 1000–当前年份+1                         | 空       |
| 标签            | string[]     | 最多 10 个，每个 1–24 字符              | `[]`     |
| 轴名            | string       | 1–24 字符；当前评价中不允许规范化后重名 | 模式预设 |
| 正向分数        | integer      | `0` 表示未评分；有效评分为整数 1–10     | 未评分   |
| 重要等级        | integer      | LV0–LV6                                 | LV3      |
| 负面分数        | number       | -5–0，步长 0.1                          | 0        |
| 单项理由        | string       | 0–500 字符                              | 空       |
| 总体评价        | string       | 0–2000 字符                             | 空       |
| 个人故事        | string       | 0–3000 字符                             | 空       |
| 本地封面        | image        | JPEG/PNG/WebP；导入上限 10 MB           | 空       |

字符上限按 Unicode 字素簇计数，前后空白在提交/导出时去除，不修改正文内部空白。

艺术家/专辑名称的 `null` 表示尚未改写，界面显示当前语言默认值但分享卡片只显示内容；非空自定义名称在卡片以“名称：内容”显示；空字符串同样只显示内容，并以浅色默认名称作为输入占位提示。用户重新输入任一受支持语言的默认名称时，必须归一化为默认语义，仍不得把该名称写入卡片。自定义条目内容为空时不进入分享卡片，但仍随草稿和完整存档保存。

### 3.1 图标评分控件

| 控件     | 图标数量   | 数值映射                               | 默认值 |
| -------- | ---------- | -------------------------------------- | ------ |
| 正向分数 | 10 颗星    | `s = 0` 表示未评分；评分区间 `[1, 10]` | 未评分 |
| 扣分项   | 5 个香蕉皮 | `n ∈ [-5, 0]`；填充量等于 `abs(n)`     | 0      |

- 星星和香蕉皮是分数输入的主要视觉控件，替代范围滑块。正向星级不提供独立数值输入；香蕉皮继续与可见的精确数值输入双向绑定。
- 点击或轻触第 N 颗星设置整数 N，键盘方向键每次移动一整星；正向星级不存在部分填充。香蕉皮的精确数值输入和方向键继续支持 0.1 步长及部分填充。
- 正向控件初始为空；首次选择得到整数 1–10，之后不得低于 1。香蕉皮从左到右表示扣分强度 0 → 5，对应存储值 0 → -5。
- 正向星级不提供“归零”按钮；未操作的 `0` 只是“未评分”状态，不是零星评价。香蕉皮仍提供归零，因为 0 表示没有扣分。
- 正向界面在未评分时显示“未评分，不计分”，评分后显示 `x.x / 10`；负面项显示 `扣 x.x（存储值 -x.x）`。不得仅靠图标数量或颜色传达状态、数值和正负方向。
- 星级控件采用纵向紧凑的 32×40 CSS px 单星热区（高度比宽度增加 25%），仍高于 WCAG 2.2 AA 的 24×24 CSS px 最小目标；香蕉皮维持 44×44 CSS px。
- 桌面端轴名称与评分区按 40%/60% 分栏，名称填写空间相对原等分布局缩短 20%，1280 px 及以上验收视口必须完整显示 10 颗星且星条不得横向滚动。
- 此规则保持 Schema v2，但把算法升级为 `music-linear-100-v4`：未评分正向轴从综合分的分子和权重分母中排除，也不出现在评分卡分项或图表中。

## 4. 模式切换

- 首次进入默认使用简易模式。
- 若当前轴仍等于模式默认值，切换模式可直接替换。
- 若用户已修改轴、分数或理由，切换前必须提示：
  - 保留现有内容并仅更改模式标签；或
  - 使用目标模式默认轴重置轴数据。
- 切换不得影响作品信息、总体评价、故事、封面与卡片样式。

## 5. 评分算法

### 5.1 等级权重

| 等级 | LV0 |  LV1 |  LV2 | LV3 | LV4 | LV5 | LV6 |
| ---- | --: | ---: | ---: | --: | --: | --: | --: |
| 权重 |   0 | 0.25 | 0.75 | 1.0 | 1.5 | 2.5 | 5.0 |

LV0 表示展示该轴但不计入综合分。停用轴既不展示也不计算。

### 5.2 计算公式

设 `R` 为“已启用、评分在 1–10 且权重大于 0”的正向轴集合，分数为 `sᵢ`、权重为 `wᵢ`；所有启用负面项分数为 `nⱼ`（-5–0）：

```text
positive100 = 10 × Σ(i∈R)(sᵢ × wᵢ) / Σ(i∈R)(wᵢ)
penalty100  = 10 × Σ(nⱼ)
rawScore100 = clamp(positive100 + penalty100, 0, 100)
score100    = round(rawScore100 × 10) / 10
```

- 这是线性算法：正向轴每增加 1 分，会按其归一化权重线性增加最多 10 个百分制分；负面项每减少 1 分，综合分固定减少 10 分。
- 未评分轴不作数：既不贡献分数，也不稀释已评分轴的归一化权重；`0` 不能解释为零分评价。
- 中间计算始终使用未舍入值，只在最终显示时把 `score100` 四舍五入至 1 位小数。
- UI、评价卡片和辅助技术文本只显示 `score100 / 100`，不得显示十分制综合分。
- 若 `R` 为空，综合分显示“无法计算”，并引导用户至少为一个 LV1–LV6 轴打 1–10 分。
- 负面项的累加扣分可能较强，因此添加第二个及以上负面项时应显示提示。
- 导出 JSON 同时保存输入值与算法版本，不把计算结果作为唯一数据源。

示例：8 分（LV4）、7 分（LV5）、9 分（LV3），负面项 -1：

```text
positive100 = 10 × (8×1.5 + 7×2.5 + 9×1) / (1.5 + 2.5 + 1) = 77
penalty100  = 10 × (-1) = -10
rawScore100 = 67
score100    = 67.0
```

### 5.3 可视化

- 雷达图仅绘制已评分的启用正向轴，固定刻度 0–10；未评分轴不显示为 0 分数据点。
- 少于 3 个已评分正向轴时，改用水平条形图，避免无意义多边形。
- 负面项用独立列表或向左延伸的条形图展示，范围 -5–0。
- 图表旁必须提供同等信息的文本列表。卡片中每个正向分项只使用一个合并条目，同时展示分项名称、精确分数和非空理由；不得再分别生成“分项评分”和“分项理由”两个重复区域。
- 雷达图自身的独立图例继续保留，至少显示每个启用轴的名称和精确分数；合并文本条目不能替代或移除雷达图图例。
- 文本分项可以复用星星/香蕉皮图标，但必须同时显示精确数字；雷达图和条形图不会被图标控件替代。

## 6. 自动保存和恢复

- 当前工作区使用固定键 `xdrate.music.workspace.v2`，恢复状态使用 `xdrate.music.recovery-state.v1`；旧工作区键只用于兼容迁移。
- 输入变化后 800 ms 防抖保存；页面进入后台及关闭前再尝试同步保存一次。
- 页面显示最近成功保存时间。
- 浏览器配额不足、序列化失败或存储不可用时，进入 `save-error`，提示用户立即导出 JSON。
- “新建评价”先建立新的内存对象，成功保存后再替换旧草稿；不得先删除旧数据。
- 未正常解决的编辑会话在下次启动时必须先显示摘要。采用恢复副本前不得把它静默写入编辑器；恢复只改变内存工作区，不写入磁盘文件。
- 恢复选择未完成时暂停自动保存，防止空白启动状态覆盖候选草稿。明确放弃或成功打开/新建/保存后清除待恢复标记，但保留正常本地工作区数据。

## 7. 模板

跨平台“评分结构模板”包含：名称、模式、评价轴定义、负面项定义、卡片显示配置、创建/更新时间和数据版本。

评分结构模板不包含：作品元数据、封面、任何评价文本、分数。应用结构模板时，用户可选择保留当前分数并按轴 ID/规范化名称匹配；默认安全行为为清空分数并加载模板结构。

### 7.1 小红书小工具内容模板

小工具另设“内容模板”，不得与评分结构模板共用格式或存储键。内容模板保存当前作品元数据、模式、评价轴、整星分数、重要等级、分项理由、负面项、总体评价和故事；不保存封面二进制、Blob URL、界面语言或临时导出结果。内容模板中的 `coverDataUrl` 固定为 `null`，套用后由用户重新选择本地封面。

- 小工具继续把当前完整输入自动保存为“最近草稿”；普通关闭和再次打开后应恢复上次输入。
- 用户可把当前输入“另存为内容模板”，并对所有内容模板执行套用、重命名和删除；覆盖同名模板与删除模板前必须确认。
- 《海棠仙》只是首次初始化时创建的普通内容模板；创建后与用户模板权限相同，可以套用、改名、覆盖或删除。
- 第一次初始化模板目录时，应用写入《海棠仙》并把它用于开局草稿，同时记录种子版本。以后有效最近草稿始终优先；已经初始化但没有有效草稿时创建空白简易草稿，不得重新生成已删除或已改名的《海棠仙》。清除全部小工具本地数据后视为新的首次初始化。
- 损坏草稿必须隔离并提示，不能覆盖模板目录；本地存储不可用时可在内存中载入《海棠仙》开局内容，但必须显示未保存状态。
- 本地内容模板在正常关闭/重开后长期保留，但仍属于平台可清理的本地缓存，不承诺卸载、清除小工具数据或平台回收空间后仍存在。
- 首版最多保存 20 个内容模板（包含首次创建的《海棠仙》）；模板名去除首尾空白后为 1–40 字符，目录序列化后最多 512 KiB。达到数量、大小或配额上限时拒绝新写入，保留当前草稿和原模板目录。

首次初始化时创建的《海棠仙》开局模板固定为：作品《海棠仙》、艺术家“纯白；星尘”、专辑“中华少女”、年份“2004”、简易模式；艺术品质 8 星（理由“采用了高几个八度的离调”）、听感 7 星（理由“当时全新出炉的星尘V4”）、个人喜好 9 星（理由“禁忌组99”），三轴均为 LV3；无负面项、总体评价为空，故事为“17年网易云从甲铁城的配乐心动到了《白·棠·彩》，注意到了这三首歌”。该夹具的综合分必须为 `80.0 / 100`。创建成功后它不再具有特殊保护。

## 8. JSON 导入/导出

- 完整存档扩展名：`.xdrate.json`；MIME 使用 `application/json`。
- 模板扩展名：`.xdrate-template.json`。
- 导出采用 UTF-8、2 空格缩进，不包含对象 URL 或临时缓存。
- 封面可作为压缩后的 Data URL 内嵌；导出前显示预计文件大小。
- 导入顺序：读取 → JSON 解析 → Schema 校验 → 版本迁移 → 预览摘要 → 用户确认 → 写入。
- 未知的更高主版本必须拒绝导入并保留当前编辑状态。

## 9. 图片导出

1. 校验作品名与可计算分数。
2. 等待字体与封面解码完成。
3. 把导出节点复制到固定尺寸的离屏容器。
4. 使用 `html-to-image` 生成 PNG。
5. 触发本地下载并恢复 UI 状态。

导出节点不得包含交互控件、焦点环或隐藏的用户数据。若浏览器因画布污染、内存不足或字体失败而报错，应给出缩小倍率、移除封面或重试的建议。

### 9.1 比例与布局族

- 横向：16:9、8:5、3:2；使用横向双栏紧凑布局。
- 准横向：4:3、5:4；使用均衡双栏布局。
- 方形：1:1；使用上下组合布局并限制正文摘要。
- 纵向：4:5、3:4、2:3、5:8、9:16；使用纵向堆叠布局，随高度逐步增加可显示文本量。

### 9.2 字体与溢出门禁

- 卡片必须设置明确的字体族、字号、行高、字距、最大行数和内容区尺寸，不得依赖浏览器默认行高。
- 在预览稳定和导出前依次等待 `document.fonts.ready`、封面解码及下一帧布局完成。
- 对所有标题、正文、图表标签和页脚检查 `scrollWidth ≤ clientWidth` 且 `scrollHeight ≤ clientHeight`。
- 雷达图轴名优先放入独立图例；不得让 SVG 文本依靠固定半径堆叠在图边缘。
- 发现溢出时应标记具体区域，提供缩短文本、隐藏可选字段或改用更高比例的操作；未通过检查不得导出。

## 10. 错误与确认规则

- 表单错误显示在字段附近，并在提交/导出时聚焦首个错误。
- 删除模板、清空草稿、覆盖导入必须确认。
- 普通字段修改、保存和下载无需确认。
- 错误信息须说明发生了什么、数据是否安全、用户下一步可以做什么。

### 10.1 未保存修改保护

- 当工作区为脏状态时，新建、打开其他存档、关闭窗口和退出应用必须进入同一个三选一流程：保存并继续、放弃修改、取消。
- “保存并继续”只有在磁盘保存成功后才执行原动作；保存对话框取消或保存失败均保留当前窗口、数据和脏状态。
- “放弃修改”不写入磁盘并执行原动作；“取消”不执行原动作。
- 自动草稿只是恢复副本，不等同于用户文件已保存，不能绕过本保护。
- 桌面端拦截 Tauri 当前窗口的关闭请求；浏览器端在脏状态下使用平台原生 `beforeunload` 警告，文案和按钮由浏览器控制。

### 10.2 桌面标题、命令与最近文件

- 窗口标题格式为“作品名或文件基名 + 可选未保存 `*` + XDRate Music”；不得显示完整路径。保存取消或失败保留 `*`，仅保存成功后移除。
- 桌面快捷键固定为：`Ctrl+N` 新建、`Ctrl+O` 打开、`Ctrl+S` 保存、`Ctrl+Shift+S` 另存、`Ctrl+Shift+E` 导出 PNG、`Ctrl+Q` 退出；所有命令保留可见、可访问的界面入口。
- 快捷键只匹配精确组合，不拦截文本编辑常用组合或普通按键；受保护操作取消后归还触发前焦点。
- 最近文件以 `xdrate.music.recent-files.v1` 保存至多 10 条显示名、用户已选路径和时间，规范化去重并按最新使用排序；不保存内容、不扫描目录、不自动打开。
