# 开发计划与版本路线

## 1. 交付策略

先完成可验证、完全离线的 Web MVP，再依次扩展 Windows 桌面、小红书小工具和独立移动端。里程碑以可演示、可测试的纵向功能切片划分，不以纯技术层完成度划分。

## 2. v0.1 Web MVP

### M0：项目基线（1–2 天）

- 初始化 React、TypeScript、Vite、Tailwind。
- 配置严格类型、格式化、Lint、单元测试和 CI。
- 建立领域、功能、基础设施目录和中英文消息框架。
- 完成条件：空应用可构建、测试、部署；质量命令在本地与 CI 一致。

### M1：评分核心（2–4 天）

- 实现数据模型、默认模式、轴编辑和评分算法。
- 实现作品信息、理由与故事表单。
- 实现分数明细和无障碍文本结果。
- 完成条件：不依赖存储和图片导出即可完成一次评分；算法边界测试通过。

### M2：预览与图片导出（2–4 天）

- 实现卡片视图模型、雷达图/条形图、主题与响应式预览。
- 实现本地封面处理、PNG 导出、合法文件名和错误恢复。
- 完成条件：11 种卡片比例在中英文及长文本下可用，字体无重合/越界，1×/2× PNG 与预览一致。

### M3：存档与模板（2–4 天）

- 实现自动保存、启动恢复、偏好。
- 实现完整 JSON 导入/导出、Schema 校验和 v1 迁移框架。
- 实现模板增删改用。
- 完成条件：刷新恢复、跨浏览器文件导入、错误文件保护当前数据等用例通过。

### M4：发布加固（2–3 天）

- 完成响应式、键盘、对比度和读屏检查。
- 执行跨浏览器端到端测试、性能检查、依赖审计和免责声明检查。
- 编写用户说明、变更记录与发布包。
- 完成条件：满足[测试与验收](./07_测试与验收.md)发布门槛。

估算总计约 9–17 个有效开发日；具体时间取决于视觉细节和跨浏览器导出兼容性。

## 3. v0.2 桌面版

- 使用 Tauri 包装 Web 前端。
- 增加原生文件打开/保存、最近文件和可选自动更新。
- 目标产物至少包括 Windows 安装包；是否提供便携版由发布策略决定。
- 桌面应用名称在品牌决策后确定，不预先固定为 `Polyrate Music.exe`。
- 详细范围、依赖、原子任务和发布门槛见 [V0.2 桌面版开发计划](./11_V0.2_开发计划.md)。

## 4. v0.3.0 小红书小工具版

- 以离线 ZIP 形式交付，ZIP 根目录必须直接包含唯一入口 `index.html`，所有运行资源随包提供且使用相对路径。
- 复用评分领域、`music-linear-100-v4`、Archive Schema v2 数据结构和评分卡视图模型；新增独立的小工具构建入口、平台适配器及兼容样式层。
- 最终 JavaScript 以 ES2017 / Chrome 61 为兼容基线并输出经典脚本，不得包含 ESM、网络请求、Worker、WASM、远程字体、外链或任意文件下载。
- 核心闭环为“本地填写 → 本地预览 → 生成 PNG → 经小红书 JSBridge 写入临时文件并保存到相册”；直接发布笔记属于单独产品门槛，默认不进入首个 MVP。
- 小工具容器不能复刻桌面任意 JSON 文件打开/保存：v0.3.0 仅保证容器本地草稿恢复，且明确提示容器数据不属于永久备份。
- 详细范围、里程碑、兼容矩阵、性能预算与 ZIP 验收规则见 [V0.3.0 小红书小工具开发计划](./23_V0.3.0_小红书小工具开发计划.md)。

## 5. v0.3.1 Bili Toy 当前版本适配

在进入独立移动 App 前，先把当前 v0.3.1 评分卡和离线能力适配为 B 站 Toy。该适配使用独立构建入口和输出目录，不改变小红书小工具、桌面版或 Web 主线；不复制小红书 JSBridge，不新增 B 站云存储、排行榜或账号能力。

- M0：安装并发现官方 `toy` CLI，盘点当前版本边界，冻结 Bili Toy 依赖清单和版本标识。
- M1：建立 Bili Toy 页面壳、相对资源、子路径兼容、中文/英文和当前音乐评分闭环。
- M2：完成 11 种比例、预览/PNG 一致性、模板、草稿、封面、键盘/窄屏和读屏回归；运行 `toy_doctor.py`，ERROR 必须为 0。
- M3：产出 `0.3.1-toy-rc.1`，执行 `toy` CLI JSON 预览；用户明确确认前不得使用 `--yes` 提交审核。
- M4：记录 Toy 预览、审核状态、线上子路径 Smoke 和已知限制；审核失败时升高候选序号，不覆盖旧包或旧哈希。

完整工作包、验收矩阵和 CLI 闸门见 [V0.3.1 Bili Toy 当前版本适配开发计划](./37_V0.3.1_BiliToy_当前版本适配开发计划.md)。

## 6. v0.4.0 独立移动 App 验证版

原 v0.3 移动版计划整体顺延至 v0.4.0，并明确定位为独立移动 App 验证版。以音乐场景先验证响应式 PWA 与 Tauri Mobile，其中 Tauri Mobile 是原生壳首选方向，PWA 是复用、性能和无障碍对照；只有关键插件不可用、性能/无障碍不达标或必要原生交互无法可靠实现时才评估 Flutter。任何重写决定必须包含维护成本、算法一致性和数据兼容方案。小红书小工具的 JSBridge 和 ZIP 约束不得反向污染独立移动端架构。

本版同时建立声明式多领域评分内核，以动漫、书籍和影视作为内部契约夹具，但公开产品仍以音乐流程验证为主，不提前发布未经研究的多领域默认轴。详细目标、里程碑、设备矩阵及 1.0.0 交接物见 [V0.4.0 独立移动 App 与多领域内核验证计划](./36_V0.4.0_独立移动App与多领域内核验证计划.md)。

## 7. v1.0.0 多领域评分器与未来能力

- `XDRate` 1.0.0 定位为多领域评分器，首要候选领域包括音乐、动漫、书籍和影视；其他领域须经独立研究和产品确认。
- 抽取通用多维评分引擎，为 `XDRate {Domain}` 领域预设提供同一套算法、存档、迁移和评分卡契约。
- 更复杂的分数区间（如 -4–9、-3–10）通过规则配置实现，不硬编码在 UI。
- v0.4.0 只验证多领域内核，不冻结 1.0.0 的最终领域轴；1.0.0 的领域名单、默认规则、Schema 和首发平台必须由 v0.4.0 证据评审后确认。
- 政治相关维度、10 分限制和密码解锁属于高敏感、规则不清晰的未来议题；在完成威胁建模、法律评估与明确产品需求前不得实现。

## 7. 版本与分支

- 使用语义化版本：`0.1.0`、`0.2.0` 等。
- 功能分支短生命周期，通过 Pull Request 合并到 `main`。
- 每个发布标签附变更记录、已知问题、数据格式版本和算法版本。
- 破坏性存档变更必须提升 Schema 主版本，并提供迁移或明确不兼容提示。

## 8. 单项任务完成定义

一项功能只有在以下条件全部满足时才算完成：

- 需求与边界已实现，空状态、错误状态和加载状态可用；
- 新增逻辑有与风险匹配的自动化测试；
- 键盘与当前目标桌面视图已人工检查；只有版本范围包含移动端时，移动视图才进入发布门槛；
- 无 TypeScript、Lint、测试或构建错误；
- 中英文文案键完整；
- 相关开发文档和变更记录已更新；
- 不引入未披露的网络请求或用户数据收集。
