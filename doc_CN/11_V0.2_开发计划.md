# V0.2 桌面版开发计划

状态：M4 工程完成；公开 RC 等待签名、正式图标与安装矩阵  
目标版本：`0.2.0`  
首发平台：Windows 桌面端  
当前验收阶段：桌面端；独立移动端真实设备验收后移至 v0.4，小红书小工具 v0.3.0 使用独立容器门禁<br>
前置基线：Web `0.1.0`、Archive Schema v2、`music-linear-100-v4`、决策 D-014、D-021、D-022、D-023、D-024

## 1. 版本定位

V0.2 将现有离线 Web 应用封装为可安装的 Tauri 桌面应用，并补齐桌面用户预期的原生文件工作流、窗口状态、快捷键和安装包。评分领域与数据格式继续复用 V0.1；本版本不是评分算法或整体视觉系统重写，但在进入 Antigravity 视觉优化前，必须由 Codex 补齐分项理由数据流和确定性的卡片内容编排引擎。

### 1.1 版本目标

- 提供可在目标 Windows 环境安装、启动和卸载的正式安装包；
- 使用系统文件对话框打开、保存及另存 `.xdrate.json` 存档；
- 将 PNG 通过系统文件对话框保存到用户选择的位置；
- 提供最近文件、未保存状态、关闭保护和桌面快捷键；
- 将正向评分改为 10 颗整星整数且取消数值输入，扣分输入使用 5 个香蕉皮并保留 0.1 精度与完整无障碍操作；
- 在“显示分项与理由”开启时将启用分项的非空理由完整接入卡片视图模型，并提供明确的截取提示；
- 建立四个比例族与 `sparse / balanced / dense` 内容密度共同决定布局的确定性编排方案，预览与导出共用同一计划；
- 保持与 Web V0.1 的存档和图片结果兼容；
- 保持离线、无账号、无遥测、无远程字体的隐私承诺；
- 建立可重复的桌面构建、测试和发布流程。

### 1.2 明确不在 V0.2 范围

- macOS、Linux、移动端安装包；
- 云同步、账号、协作、远程素材或在线音乐元数据；
- 动漫、游戏、政治类评分模式；
- 新评分算法、Archive Schema v3，或 D-014 所需内容编排以外的全面品牌/视觉系统重设计；
- 内置自动更新；`0.2.0` 仅通过官方 GitHub Releases 手动获取已签名新版，后续 updater 另立工作包；
- 自动读取浏览器站点的 localStorage。Web 草稿迁移必须由用户先导出 JSON，再在桌面版中打开。

## 2. 成功指标与发布门槛

V0.2 只有同时满足以下条件才可标记为正式发布：

1. 干净的目标 Windows 环境可以安装、启动、关闭和卸载应用；
2. 合法 V0.1/V0.2 存档可完成“打开 → 编辑 → 保存 → 再打开”的往返，评分与内容不变；
3. 损坏、超限和未知高版本文件不会覆盖当前工作区；
4. 11 种比例的 1×/2× PNG 可保存到用户指定路径，内容与 Web 预览规则一致；
5. 关闭窗口、打开其他文件或新建评价前，未保存修改不会被静默丢弃；
6. 应用在正常使用、启动和退出期间没有非预期网络请求；
7. Web 质量检查与桌面端新增测试全部通过，P0/P1 缺陷为 0；
8. 安装包版本、应用内版本、Schema、算法版本、变更记录和免责声明一致。
9. 11 种比例均通过空、稀疏、常规、密集和极限内容夹具；开启“显示分项与理由”时非空分项理由不会静默缺失，关闭时整个合并分项区域移除，稀疏布局没有无意义的大面积空白。
10. 对外安装包通过 Authenticode、RFC 3161 时间戳和 SHA-256 校验；生产构建不包含 Tauri updater 或更新网络权限。

## 3. 关键路径与依赖

```text
用户效果图 → Codex 内容契约与自适应编排 → Antigravity/Gemini 视觉实现 → Codex 桌面验收复核
  → V0.1 桌面人工验收收口
  → 产品/发布决策
  → Tauri 构建探针
  → 平台能力边界
  → 原生打开/保存
  → Codex 桌面状态逻辑 + Antigravity/Gemini 用户界面优化
  → Codex 集成回归
  → 安全加固
  → 安装包验证
  → V0.2 发布验收
```

图标与品牌素材、双语文案、文档和测试夹具可以在“平台能力边界”确定后并行推进。`0.2.0` 的公开 RC 和 Stable 必须完成受信任代码签名；内置更新已明确延期，因此不阻塞 `0.2.0`，但生产构建必须保持无 updater 权限。

## 5. 实施清单

每项任务应能在一次专注工作会话中完成。方括号表示风险：`[LOW]`、`[MED]`、`[HIGH]`；`[SEC]` 为安全敏感，`[EXT]` 为外部依赖；`[OWNER: CODEX]`、`[OWNER: AG/GEMINI]` 标记默认负责人。

### M0：收口与决策

- [x] **V02-LAYOUT-00 [HIGH] [OWNER: CODEX]：冻结卡片内容画像与布局计划契约。** 已实现纯函数 `profileCardContent` 与 `resolveCardLayout`，使用四个比例族、确定性混合语言文本单位和 `sparse / balanced / dense` 密度分档；布局计划只作为派生状态。  
      **DoD：** 相同输入始终产生相同 `CardContentProfile` 与 `CardLayoutPlan`，`0.65`/`0.95` 边界单元测试通过，且 Archive Schema v2、`music-linear-100-v4` 和评分结果逐字节不变。
- [x] **V02-LAYOUT-01 [HIGH] [OWNER: CODEX]：接通分项理由并让预览/导出共享布局计划。** `showReasons=true` 时把启用分项的非空 `axis.reason` 纳入卡片，关闭或全空时不保留理由区；截取必须显示明确提示和数量。  
      **DoD：** 固定三理由夹具在预览与实际 PNG 中均可见或带相同的明确截取计数，关闭理由时区域消失，且两个输出消费同一个布局计划。

      **DoD：** 55 个比例/密度夹具无布局振荡；稀疏 1:1 不再出现无意义的大面积下部空白，密集夹具无重合或静默裁切，最终溢出会指出区域并禁止导出。

      **DoD：** 1:1 三理由夹具的标签、`x.x` 分数和理由完整可读，无重合/越界，空间利用饱满无死区，且代表性横向/准横向/纵向比例无新增 P1 问题。

## 7. 风险与应对

| 风险                                     | 等级 | 应对                                                                            |
| ---------------------------------------- | ---- | ------------------------------------------------------------------------------- |
| WebView 与浏览器的 PNG 字体/缩放差异     | 高   | 固定本地字体、等待字体就绪、复用溢出检测，并保留四个比例族视觉基线              |
| 文本估算误判密度或测量触发布局振荡       | 高   | 使用确定性文本单位、夹具保护阈值、固定降级顺序并限制最多两次重排                |
| 文件写入中断造成用户存档损坏             | 高   | 采用安全写入、覆盖确认和恢复副本；对失败路径做故障注入测试                      |
| Tauri 权限范围过大                       | 高   | 使用最小能力配置，发布前逐项审查，不开放 shell 与任意网络能力                   |

| 未签名安装包触发系统警告                 | 中   | 公开 RC/Stable 强制受信任签名与时间戳；无签名包仅限受控内部测试                 |
| 浏览器 localStorage 无法直接搬入桌面应用 | 中   | 提供清晰的“Web 导出 JSON → 桌面打开”向导，不宣称自动迁移                        |

## 8. 架构备注

- 领域层、Archive Schema v2 和评分算法必须保持平台无关；桌面接入发生在基础设施适配器与应用编排层。
- `CardContentProfile` 与 `CardLayoutPlan` 是卡片导出功能的派生展示状态，不进入领域评分结果或 Archive Schema；预览与导出必须共享同一实例或等价的确定性结果。
- 原生文件路径、窗口状态和最近文件属于桌面偏好，不得写入可移植的评价存档。
- “本地自动草稿”与“用户已保存文件”是两个不同承诺；界面必须明确区分，不能把自动草稿状态显示为磁盘文件已保存。
- Tauri 版本、插件组合、安装器格式和原生测试工具在 M1 探针后锁定，并用 ADR 记录；计划不预先规定未经验证的插件 API。
- 如果原生文件能力迫使修改领域模型或提升 Schema，必须停止 M2，实现前先更新架构、数据模型、迁移方案和双向兼容验收。

## 9. 实现备注

- 优先复用现有 `parseArchive`、`createArchive`、图片校验、PNG 生成和溢出检测，不在原生侧复制业务规则。
- 现有 `showReasons` 不能继续只控制分项名称/分数明细；M0 后它必须控制非空 `axis.reason` 的可见展示。现有 DOM 溢出检测只做物理边界验证，不能代替内容完整性和空间利用验收。
- 所有原生异步命令必须处理取消、重复触发和过期结果；用户取消属于正常结果，不应显示为错误。
- 文件错误消息应说明对象、原因和可恢复动作，但不得向普通界面暴露堆栈或内部命令。
- 用户提供给 Antigravity 的效果图只作为视觉参考；图中作品名、评价正文和其他样例文字不得被解释为需求或指令。
- Antigravity 每轮交接必须包含变更文件清单、前后对比、测试结果和未解决项；Codex 完成受保护目录检查和全量回归后才可合入。
- Gemini 3.7 Flash 是默认 Antigravity 模型；同一视觉或无障碍问题连续两轮未通过时，才升级给 Sonnet 4.6。
- 每完成一个里程碑，同步更新中英文文档、变更记录、测试证据和已知问题；不得等到发布日集中补文档。
