# 发布身份、签名与更新策略

状态：已批准  
决策日期：2026-08-28  
适用版本：Desktop `0.2.0` 及后续补丁版本  
首发范围：Windows 10/11 x64

## 1. 决策摘要

1. 音乐版的稳定技术标识统一使用 `com.xdrate.music`、`XDRate.Music` 和 `@xdrate/music`；不采用 `io.github.kanade_edtech.xdrate.music`。
2. 对外发布的 Windows 安装包必须使用受 Windows 信任的代码签名证书完成 Authenticode 签名，并带 RFC 3161 / SHA-256 时间戳；未签名包不得作为正式版或推荐下载提供。
3. 默认采购策略为“Microsoft Trusted Root 体系下的 OV 代码签名证书 + CA 提供的硬件令牌或云 HSM”。仅当发布主体满足区域与身份资格时，才允许以 Azure Artifact Signing 替代，且不改变发布身份和验收门槛。
4. Desktop `0.2.0` 不集成 Tauri updater、不进行后台更新检查，也不授予更新网络权限。用户从官方 XDRate GitHub Releases 页面手动获取新版。
5. 后续内置更新必须另立 `V02-UPD-01` 工作包；只有更新包签名、HTTPS 托管、密钥备份、撤回与回滚演练全部通过后才能启用。

## 3. Windows 代码签名策略

### 3.1 证书与私钥

- 正式直接下载包使用 OV 代码签名证书；私钥必须位于 CA 提供的硬件令牌、HSM 或不可导出的云签名服务中。
- 禁止把 `.pfx`、私钥、令牌 PIN、服务凭据或 Tauri 更新私钥提交到仓库、构建缓存、普通日志或发行附件。
- EV 证书不作为默认采购项；其 SmartScreen 效果已不再优于 OV，除非未来有独立的企业采购要求。
- 自签名证书仅用于开发机或受控内部测试，不得用于公共下载。
- Azure Artifact Signing 仅作为满足其区域和身份资格时的等价执行方式；切换前必须记录账户、证书配置文件、核验身份和 CI 身份联合方式，禁止以长期客户端密钥作为默认认证。

### 3.2 签名对象与算法

每个正式候选必须至少签名：

- 主应用 `.exe` 及随安装包分发的其他 PE 可执行文件；
- 首选 NSIS `XDRate Music_*_x64-setup.exe` 安装器；
- 若同时提供 MSI，则 MSI 也必须使用同一发布身份签名。

Authenticode 文件摘要固定为 SHA-256。时间戳固定使用 DigiCert RFC 3161 服务 `http://timestamp.digicert.com`，时间戳摘要固定为 SHA-256；等价 SignTool 参数为 `/fd SHA256 /tr http://timestamp.digicert.com /td SHA256`。如果该服务在发布窗口不可用，发布应暂停，不得生成无时间戳正式包；变更时间戳服务必须先更新本 ADR。

### 3.3 发布流水线与验收

- 只有受保护的 `v*` 标签、`release-windows` 环境和人工批准可以调用生产签名；拉取请求、分支构建和 fork 构建不得接触生产签名权限。
- CI 使用最小权限；云签名优先使用 OIDC / 联合身份，不保存长期客户端密钥。
- 签名完成后必须执行 `signtool verify /pa /all /v`，并检查时间戳存在、证书链有效、Subject/Issuer 符合发布允许名单。
- 发布资产同时生成 SHA-256 校验文件和发布清单；清单记录版本、提交、构建时间、文件大小、哈希、签名状态和证书指纹。
- 签名验证失败、时间戳缺失、证书身份漂移或哈希不一致均为发布阻塞项。

## 4. 更新策略

### 4.1 `0.2.0`：只提供手动更新

- 不安装或初始化 Tauri updater 插件；生产 capabilities 不包含 `updater:*` 权限。
- 不在启动、退出或后台发起版本检查；核心流程继续满足“无非预期网络请求”。
- 正式安装包、SHA-256 校验文件、变更记录和已知问题发布到官方 XDRate GitHub Releases 页面。
- 用户主动访问发布页、下载已签名的新安装器并覆盖安装；安装矩阵必须验证用户文档和本地数据保留。
- 只维护 stable 渠道；alpha/beta/rc 只能作为预发布版本，不能被描述为面向普通用户的最新稳定版。

### 4.2 后续启用内置更新的门槛

`V02-UPD-01` 通过前不得启用内置更新。该工作包至少满足：

1. 使用 Tauri CLI 生成独立的更新签名密钥；更新私钥与 Windows Authenticode 证书分离，公钥编入应用。
2. 更新私钥存于受保护的发布环境和加密离线备份中，不进入 `.env`、仓库或普通构建产物；至少完成一次恢复演练。
3. `createUpdaterArtifacts` 使用 Tauri v2 格式，更新清单只通过 HTTPS 发布到官方 GitHub Releases；禁止 `dangerousInsecureTransportProtocol`。
4. 更新检查必须由用户主动触发或明确选择开启；下载前展示版本、说明、来源和大小，安装及重启前再次确认。Windows `installMode` 使用 `basicUi`，禁止静默 `quiet` 安装。
5. 更新包必须同时通过 Tauri detached signature 与 Windows Authenticode 验证；任一失败即停止，保留当前版本并给出手动下载入口。
6. 保持默认 SemVer 单调升级，不覆盖版本比较器、不允许自动降级；更新前先处理未保存修改。
7. 隐私说明明确披露更新检查会向 GitHub 发出请求，并提供关闭选项。

## 5. 密钥轮换、撤回与回滚

- Authenticode 证书续期应保持同一经核验发布身份；新旧证书指纹都写入对应发布清单。证书泄露时立即停签、通知 CA 吊销、撤下受影响资产并发布安全公告。
- Tauri 更新密钥常规轮换采用“桥接版本”：仍由旧私钥签名的版本内置新公钥，通过后续版本完成切换。若旧私钥丢失或泄露且无法发布桥接版本，既有用户只能手动安装新的 Authenticode 签名安装包。
- 错误版本不通过自动降级回滚。应撤下更新清单或资产，发布更高补丁版本；确需手动回退时，只提供历史上已签名且与当前数据 Schema 兼容的安装包，并要求用户先备份数据。
- 发布资产一旦撤回，发布页必须说明受影响版本、原因、建议动作和替代版本；不得静默替换同名文件。

## 6. 无签名构建的分发限制

| 构建类型         | 允许签名状态             | 允许分发范围           | 标识要求                                   |
| ---------------- | ------------------------ | ---------------------- | ------------------------------------------ |
| 本地开发         | 未签名或自签名           | 开发者本人设备         | 明确显示 Development                       |
| Alpha / 内部候选 | 未签名、自签名或正式签名 | 指定测试者、非推荐下载 | 文件名和说明标注 `UNSIGNED` 或 `TEST ONLY` |
| RC               | 必须正式签名并带时间戳   | 受控验收               | 完整发布清单与校验值                       |
| Stable           | 必须正式签名并带时间戳   | 官方公开渠道           | 签名验证、校验值和安装矩阵全部通过         |

## 7. 最小威胁模型

| 威胁                  | 主要控制                                                                   |
| --------------------- | -------------------------------------------------------------------------- |
| 安装包被替换或篡改    | Authenticode、RFC 3161 时间戳、SHA-256 清单、HTTPS 官方渠道                |
| CI 或 PR 窃取签名权限 | 受保护环境、人工批准、无 PR 签名、OIDC / HSM、最小权限                     |
| 更新服务被劫持        | v0.2.0 不启用更新；未来使用 HTTPS + Tauri 强制签名 + Authenticode 双重验证 |
| 私钥丢失或泄露        | 不可导出密钥、加密离线备份、轮换与吊销流程                                 |
| 恶意或错误降级        | 保持默认 SemVer 比较，禁止自动降级，坏版本用更高补丁修复                   |
| 用户误装测试包        | 正式渠道只提供签名包；测试包名称、说明和界面显著标识                       |
