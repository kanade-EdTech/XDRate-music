# V0.4.0 分享机制实现计划

状态：M0、M1、M2、M3 已完成，M4 候选包已生成；真机与跨容器验收待完成。承接《V0.4.0 分享机制设计》，用于关闭当前代码与设计之间的差距

## 1. 目标

本计划把分享设计落成可恢复的工程闭环：用户修改内容后，预览、PNG、相册文件和平台交接必须引用同一份可追踪的卡片快照；外部调用前保存确认内容；返回、取消、拒绝、失败或刷新后不丢失内容，也不产生无法解释的重复提交。

v0.4.0 的平台目标仍按能力分级执行：相册保存和本地 PNG 是基础能力，系统分享是通用能力，平台专用 Bridge 只在能力探测通过时启用。没有官方接口的平台不进入伪直连发布范围。

## 3. 版本边界

### 必须完成

- 预览快照失效与重新生成机制。
- 调用前持久化、确认页实时恢复和 accepted 后的幂等收口。
- 相册、导出、系统分享和小红书 Bridge 的结果分类。
- “个人签名档（可选）”在预览、PNG、相册和帖子交接中的一致性。
- 11 种比例、修改后再导出、刷新恢复和重复提交防护验收。

### 本版不承诺

- QQ 空间、B 站动态、微信、贴吧、知乎或微博的无官方接口直连发布。
- 平台公开状态、帖子 ID 或第三方账号登录态的读取。
- 后台自动重试、云端中转和社交平台数据同步。

## 4. 实施阶段

### M0：卡片快照与失效控制

1. 为评分内容、比例、主题、封面和签名档生成稳定的 `renderRevision` 或内容指纹。
2. `preview` 保存 `{ dataUri, renderRevision, ratio, generatedAt }`，所有评分、文本、封面、比例和清除操作都使旧快照变为 stale。
3. 预览和相册只接受当前 revision；平台交接遇到旧快照时必须明确提供“生成新图片 / 分享旧图片 / 取消”，不能静默复用。
4. 为异步 Canvas 生成增加请求序号，后完成的旧任务不能覆盖新内容。
5. 统一 `CardSnapshot`，使桌面导出和小工具导出至少共享输入、尺寸和算法版本。

完成证据：修改评分、修改封面、清除默认内容、切换比例后，旧预览不能被相册静默复用；分享时必须经过三选一确认。

当前实现：`src/minitool/renderRevision.ts` 提供确定性内容指纹；小工具预览记录生成时的 revision；旧 PNG 会被标记为过期，不能保存到相册或交给小红书；异步生成任务在内容变化后不会覆盖新内容。定向单测、TypeScript 检查和小工具生产构建已通过。

### M1：确认页持久化与幂等恢复

1. 将 pending post Schema 升级为 v2，保存 `requestId`、`renderRevision`、目标容器、确认文字、图片摘要、创建时间和状态。
2. 标题、正文、标签和签名档在确认页修改后进行防抖保存；`pagehide`、`visibilitychange` 和刷新都恢复最后一次确认内容。
3. 提交前先保存工作区与 pending request；保存失败时禁止调用 Bridge。
4. `accepted` 后清除可提交的 pending payload，保留一条不可自动重试的本地交接记录。
5. 恢复时只展示“上次交接已受理”或“可恢复确认”，不得自动再次调用平台。
6. 增加“放弃本次确认”操作，清除 pending payload，但不清除评分草稿。

完成证据：确认页编辑后强制刷新仍保留；accepted 后刷新不会再次调用 `postNote`；取消可以继续编辑并重新生成新的 `requestId`。

当前实现：`postNoteStorage.ts` 升级为 v2 Schema，记录 `requestId`、`renderRevision`、目标、时间和交接状态；确认页文字编辑采用 250ms 防抖写入，提交前先写入工作区和 pending request；`accepted` 记录保留为不可自动重试状态，刷新只恢复提示；“放弃本次确认”会清除 pending 记录而不清除评分草稿。定向单测、TypeScript 检查和小工具生产构建已通过。

### M2：平台能力与失败分类

1. 扩展统一结果类型：`completed`、`accepted`、`cancelled`、`denied`、`failed`、`unavailable`、`unknown`。
2. 将 Bridge 错误映射为权限拒绝、用户取消、临时文件失败、相册写入失败和帖子调用失败。
3. Bridge 未检测到时禁用不可执行的相册/发布按钮，并提供本地 PNG 降级入口。
4. 桌面导出明确区分成功、用户取消和写入失败；浏览器端增加能力探测后的系统分享入口。
5. 建立平台适配器窄接口，业务层只依赖 `ShareRequest`、`ShareResult` 和恢复记录。

完成证据：每一种结果都有独立用户文案和可执行下一步；无 Bridge 时仍可编辑、预览和导出。

当前实现：`minitoolBridge.ts` 统一返回 `completed/accepted/cancelled/denied/failed/unavailable/unknown` 结果；相册临时文件失败、相册写入失败、权限拒绝、Bridge 缺失和未知异常分别分类；MiniTool 界面为相册和发帖提供独立恢复文案。Bridge 单测覆盖拒绝、取消、不可用、失败和未知异常。

### M3：个人签名档与一致性

1. 在本地草稿、Archive Schema 和确认页增加“个人签名档（可选）”。
2. 空值不占卡片布局，不参与评分；非空值按长度限制安全截断。
3. 桌面卡片、小工具 Canvas、PNG、相册文件和帖子正文使用同一个已确认值。
4. 为 11 种比例建立预览/导出/相册输入一致性夹具；覆盖长标题、长签名、无封面、封面、空故事和多评价轴。
5. 记录字体加载、Canvas 生成和系统分享返回时的可追踪信息，不保存账号令牌。

完成证据：签名档在所有输出路径位置一致；清空签名档后不残留空白占位或旧文本。

当前实现：评分草稿、Archive Schema、桌面编辑器、桌面卡片 Footer、MiniTool Canvas、PNG 和小红书确认正文均支持“个人签名档（可选）”；空值不占位，非空值限制 120 字并参与 render revision。桌面与 MiniTool 生产构建、全量单测已通过。

### M4：发布验收与包体交接

1. 运行定向单测、桌面 E2E、MiniTool Bridge E2E 和 11 比例视觉矩阵。
2. 真机验证相册授权首次允许、拒绝、再次允许、取消、系统清理缓存和返回恢复。
3. 验证小红书 `postNote` 单次调用、accepted 后刷新、cancelled 重试和失败重试。
4. 验证桌面导出取消、系统分享不可用、浏览器刷新和文件下载失败。
5. 生成中英文变更记录、测试摘要、包体哈希和已知平台边界，作为 v0.4.0 候选包门禁。

## 5. 推荐数据结构

```ts
interface CardSnapshot {
  renderRevision: string;
  ratio: CardRatio;
  width: number;
  height: number;
  pngDataUri: string;
  algorithm: 'music-linear-100-v4';
  generatedAt: string;
}

interface PendingShareRequest {
  requestId: string;
  source: 'desktop' | 'web' | 'minitool' | 'toy' | 'wechat';
  target: ShareTarget;
  snapshot: CardSnapshot;
  text: { title?: string; content?: string; tags?: string; personalSignature?: string };
  state: 'confirming' | 'persisted' | 'invoking' | 'accepted' | 'cancelled' | 'failed';
  updatedAt: string;
}
```

## 6. 测试用例清单

| 类别     | 必测场景                         | 预期                                                  |
| -------- | -------------------------------- | ----------------------------------------------------- |
| 快照     | 生成后修改分数、理由、封面、比例 | 旧 PNG 标记 stale，不允许保存/发布                    |
| 清除     | 生成后点击一键清除               | 预览、帖子草稿和相册动作都指向空白新 revision         |
| 恢复     | 确认页修改后刷新/隐藏/崩溃恢复   | 最后一次确认文字和图片完整恢复                        |
| 幂等     | accepted 后刷新、重复点击提交    | 不自动重复调用，不产生第二个 requestId 以外的隐式提交 |
| 权限     | 首次拒绝、再次授权、取消系统面板 | 分别显示 denied、completed 或 cancelled               |
| 能力缺失 | 无 Bridge、无系统分享            | 本地编辑和 PNG 导出仍可用                             |
| 输出     | 11 比例与签名档开关              | 预览、PNG、相册和交接输入一致                         |

## 7. 完成定义

- P0 缺口 G1、G2、G3 全部关闭。
- P1 缺口 G4、G5、G6、G7 至少完成代码和自动化证据；G8 完成视觉门禁或记录已接受差异。
- `ShareRequest`、`ShareResult`、pending Schema 和错误映射在中英文文档、实现和测试中保持一致。
- 所有平台边界文案不把 accepted 写成已公开，不把系统分享写成目标平台已发布。
- v0.4.0 候选包可在无 Bridge 环境下完成编辑、预览和本地 PNG 导出。
