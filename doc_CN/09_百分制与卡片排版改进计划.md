# 百分制与卡片排版改进计划

> 历史实施说明：本计划记录已完成的 `music-linear-100-v3` 阶段。现行正向评分语义已由 D-021、D-023 / `music-linear-100-v4` 取代：未评分轴不作数，首次评分后最低一星，且只允许整星整数输入。

状态：自动化实施、功能回归与视觉基线已完成；真实设备人工验收待执行  
目标版本：v0.1.1  
优先级：P0

## 1. 改进目标

本轮解决四个已确认问题：

1. 综合总分只使用 0–100，保留 1 位小数，不再展示十分制综合分。
2. 评分算法以明确、可解释、可测试的线性公式实现并展示。
3. 修复卡片预览和 PNG 导出中共同存在的字体重合、SVG 标签碰撞和文本越界。
4. 将卡片比例从 3 种扩展到 11 种：16:9、8:5、3:2、4:3、5:4、1:1、4:5、3:4、2:3、5:8、9:16。

## 2. 影响范围

| 模块                     | 主要修改                                        |
| ------------------------ | ----------------------------------------------- |
| `domain/rating`          | 将结果模型改为百分制，更新算法版本和单元测试    |
| `features/rating-editor` | 删除十分制总分文案，贡献明细统一转换为百分制    |
| `features/card-export`   | 扩展比例、建立布局族、重做图表标签和溢出检测    |
| `domain/archive`         | 更新 CardRatio Schema 与算法版本，迁移旧存档    |
| `i18n`                   | 更新百分制、比例、溢出错误和修复建议文案        |
| `e2e`                    | 加入 11 比例截图、溢出门禁及预览/导出一致性测试 |

## 3. 工作包

### WP-1：百分制领域算法

状态：已完成（2026-08-22）

- 把 `RatingResult` 中的公开综合分收敛为 `score100`，删除 UI 使用的 `score10`。
- 按[功能规格](./02_功能规格.md#52-计算公式)实现 `music-linear-100-v3`；LV0–LV6 权重为 0、0.25、0.75、1、1.5、2.5、5，默认 LV3。
- 保留各轴 0–10 输入，不改变滑块和模板中的原始分数。
- 所有贡献明细使用百分制：单轴贡献 `10 × sᵢ × wᵢ / Σ(wᵢ)`。
- 最终值保留 1 位小数；不得提前舍入中间值。
- 更新属性测试、固定示例和上下界测试。

完成条件：任何 UI、辅助技术文本和导出卡片均不出现十分制综合分；修订权重后的示例结果为 67.0/100。

### WP-2：存档兼容

状态：已完成（2026-08-22）

- 新算法标识为 `music-linear-100-v3`。
- CardRatio 使用明确比例字符串。
- 迁移旧值：`wide → 16:9`、`square → 1:1`、`portrait → 4:5`。
- 旧存档没有持久化综合结果，因此保留轴和负面输入后重新计算，不丢失用户内容。
- 为 v1 → 当前格式增加固定迁移夹具；高版本继续拒绝导入。

完成条件：三种旧比例均正确迁移，迁移前后的作品、轴、理由、封面和正文保持一致。

### WP-3：卡片布局系统

状态：已实现并通过自动化回归（2026-08-22）

- 使用比例配置表代替三元判断：`id`、宽高、布局族、基准画布、字号令牌、内容上限。
- 建立四个布局族：横向、准横向、方形、纵向。
- 每个比例使用固定逻辑画布尺寸；页面预览只做等比缩放，避免窄侧栏改变内部排版。
- 将导出节点与页面展示容器解耦；导出节点使用稳定尺寸和相同的 Card ViewModel。
- 横向比例减少正文行数，纵向比例按高度增加内容容量。

完成条件：11 种比例都能切换、预览和导出，输出像素尺寸与选中比例误差不超过 1 px。

### WP-4：字体重合修复

状态：已实现并通过自动化回归（2026-08-22）

- 明确卡片字体栈、字号、行高、字距和各区域最小/最大高度。
- 在字体、封面和布局稳定前显示“正在准备预览”，不允许导出。
- 雷达图轴名移到外部图例，SVG 只绘制图形和短值，消除固定半径标签碰撞。
- 给标题、元数据、评分、正文、故事和页脚分配独立网格区域；禁止通过绝对定位相互覆盖。
- 增加 `detectCardOverflow()`，返回具体溢出区域和原因。
- 若内容超限，默认按比例预设截取摘要，并向用户显示实际截取情况；仍溢出时禁用导出。

完成条件：长标题、8 个雷达轴、中英文混排、最大正文夹具在所有比例中无重叠；无法容纳的内容会被明确拦截。

### WP-5：测试与回归

状态：自动化回归与确定性视觉基线已完成（2026-08-28）；真实设备人工验收待执行

- 单元测试：百分制线性、舍入、上下界、负分和比例配置完整性。
- 组件测试：比例选择、溢出提示、导出按钮门禁、隐藏可选字段。
- Playwright：11 比例 × 2 主题的 DOM 溢出断言；代表比例使用真实 2× PNG 导出做确定性视觉快照比较。
- 导出验证：读取 PNG 宽高，确认比例和 2× 像素倍率。
- 回归：自动保存、模板、JSON 往返、中英文、axe、无第三方请求。

完成条件：全部 CI 检查通过，新增或既有测试无跳过项，人工检查覆盖至少一个中英文长文本样例。

## 4. 实施顺序

```text
WP-1 百分制算法
  → WP-2 存档迁移
  → WP-3 比例与布局族
  → WP-4 溢出检测和字体修复
  → WP-5 跨比例回归与验收
```

WP-3 和 WP-4 应在同一分支完成，因为比例布局和字体容量相互影响；不得只扩展比例枚举而复用现有固定排版。

## 5. 风险与控制

| 风险                         | 控制措施                                                   |
| ---------------------------- | ---------------------------------------------------------- |
| 负分按 ×10 后影响过强        | 计算明细明确显示每项百分制扣分；保留决策项以便后续产品评估 |
| 11 种比例造成大量条件分支    | 使用配置表和 4 个布局族，不为每个比例复制组件              |
| 系统字体跨平台度量不同       | 使用保守行高、稳定字体栈、运行时溢出检测和三浏览器测试     |
| HTML 预览无重叠但 PNG 有差异 | 导出前等待字体/图片，并对实际导出节点执行同一检测          |
| 旧模板比例失效               | 提供确定映射和迁移测试，不静默回退到随机比例               |

## 6. 验收结果格式

实施完成后应在 Pull Request 或发布记录中附上：

- 新旧算法示例对照；
- 11 种比例的尺寸与布局族清单；
- 代表性横向、方形、纵向卡片截图；
- 溢出测试结果和已知文本上限；
- 存档迁移夹具结果；
- 完整质量命令与跨浏览器测试结果。
