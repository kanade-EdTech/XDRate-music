# 技术架构

## 1. 架构目标

v0.1 采用无后端、离线优先的单页应用。业务计算必须与 React UI 解耦，存储和导出通过适配器封装，以便 v0.2 接入 Tauri 时复用领域逻辑。

## 2. 技术栈

| 层        | 选型                                  | 说明                                            |
| --------- | ------------------------------------- | ----------------------------------------------- |
| UI        | React + TypeScript                    | 组件化与严格类型                                |
| 构建      | Vite                                  | 开发、构建和静态资源处理                        |
| 样式      | Tailwind CSS                          | 语义化设计令牌与响应式布局                      |
| 表单/校验 | React Hook Form + Zod（建议）         | 单一 Schema 复用于表单和导入                    |
| 状态      | Zustand 或 React reducer（择一）      | 规模较小时避免复杂全局框架                      |
| 图表      | 支持 SVG 的轻量图表库或自研 SVG       | 确保图片导出和无障碍可控                        |
| 图片导出  | html-to-image                         | DOM 卡片生成 PNG                                |
| 本地数据  | IndexedDB + localStorage 偏好         | 大封面进入 IndexedDB，轻量偏好进入 localStorage |
| 测试      | Vitest + Testing Library + Playwright | 单元、组件与端到端测试                          |
| 质量      | ESLint + Prettier + TypeScript strict | CI 统一校验                                     |

最终依赖版本在项目初始化时锁定；避免把具体版本号写死在架构文档中。

## 3. 推荐目录

```text
src/
  app/                  # 启动、路由、Provider、全局错误边界
  features/
    work-metadata/
    rating-editor/
    templates/
    archive/
    card-export/
  domain/
    rating/             # 纯类型、算法、默认轴
    archive/            # Schema、迁移、序列化
  components/           # 跨功能通用 UI
  infrastructure/
    storage/            # IndexedDB/localStorage 适配器
    image/              # 压缩、解码、导出
  i18n/
  styles/
  test/
```

依赖方向：`app/features → domain`，`infrastructure` 实现 `domain/features` 定义的接口；`domain` 不得导入 React、浏览器存储或 UI 库。

## 4. 状态与数据流

```text
UI event
  → form/store command
  → domain validation and score calculation
  → immutable rating state
  ├─→ debounced storage adapter
  └─→ card view model → preview/export
```

- 当前评价对象是唯一业务数据源。
- 综合分和图表数据是派生值，不在编辑状态中重复维护。
- 保存状态与业务状态分离，防止保存失败破坏当前输入。
- 所有异步操作支持取消或忽略过期结果，避免快速连续导出/导入导致竞态。

## 5. 领域服务

必须提供并单元测试以下纯函数：

```ts
calculateRating(input): RatingResult
normalizeAxisName(name): string
validateRatingArchive(value): ValidationResult
migrateArchive(value): CurrentArchive
createDefaultRating(mode, preferences): Rating
buildCardViewModel(rating, options): CardViewModel
sanitizeDownloadName(value): string
```

评分算法带 `algorithmVersion`。首版为 `music-weighted-v1`，首个百分制版本为 `music-linear-100-v2`，权重修订版为 `music-linear-100-v3`，当前“未评分轴排除、最低一星”版本为 `music-linear-100-v4`。算法变化若影响既有评分，必须创建新版本而非静默修改旧算法。

### 5.1 卡片内容编排服务

卡片导出功能增加两个与 React、DOM 和存储无关的纯函数；它们属于 `features/card-export` 的展示逻辑，不得修改评分算法、Archive Schema 或 `algorithmVersion`：

```ts
profileCardContent(draft, options): CardContentProfile
resolveCardLayout(config, profile): CardLayoutPlan
```

`CardContentProfile` 至少记录封面是否存在、启用分项数、非空分项理由数与文本单位、负面项数、总体评价文本单位和故事文本单位。`CardLayoutPlan` 至少记录比例族、`sparse | balanced | dense` 密度、图表尺寸、列数、理由/评价/故事行数预算、可见性和 `fallbackLevel`。该计划是派生状态，不写入存档。

混合语言文本使用确定性宽度估算：CJK 与全角字符计 1 个文本单位，拉丁字母、数字与半角字符计 0.55 个文本单位；`estimatedLines = ceil(textUnits / effectiveUnitsPerLine)`。首轮布局按下式估算需求：

```text
contentDemand = fixedHeaderHeight
              + minimumChartHeight
              + breakdownHeight
              + reasonLines × reasonLineHeight
              + commentLines × commentLineHeight
              + storyLines × storyLineHeight

density = contentDemand / usableContentHeight
```

默认阈值为 `< 0.65 → sparse`、`0.65–0.95 → balanced`、`> 0.95 → dense`。阈值属于有测试夹具保护的布局常量，只能连同 11 种比例的视觉与自动化基线一起调整。首次渲染后可测量 DOM；若溢出，按固定顺序最多将 `fallbackLevel` 提升两次。最终仍溢出时返回具体区域并阻止导出，不允许无限重排。

`showReasons=true` 时，视图模型必须包含启用分项的非空 `axis.reason`；当前只列分项名称和分数的明细组件不能视为完成理由展示。预览与 PNG 导出必须消费同一个 `CardLayoutPlan`。

## 6. 存储策略

- 用 Repository 接口封装草稿、模板和偏好，不让组件直接调用 Web Storage。
- 轻量元数据和偏好可存 localStorage；包含封面的完整草稿优先存 IndexedDB。
- 保存使用写新记录后切换引用的方式，降低中断造成损坏的风险。
- 启动时校验本地数据；损坏数据保留在隔离键中，并向用户提供导出诊断副本的入口。
- 不使用 Cookie、Service Worker 后台同步或远程日志。

PWA 离线缓存可在 v0.1 后半程加入；即使未启用 PWA，已加载页面的编辑和导出也不得依赖网络。

## 7. 图片与安全边界

- 仅接受通过 MIME、文件签名和浏览器解码验证的 JPEG/PNG/WebP。
- 压缩后建议最长边不超过 1600 px；去除不必要的 EXIF 元数据。
- 用户文本只作为文本节点渲染，不使用 `dangerouslySetInnerHTML`。
- JSON 导入视为不可信输入，限制总大小、数组长度、字符串长度和 Data URL 大小。
- 下载名移除路径分隔符、控制字符和 Windows 保留名。

## 8. 错误处理与日志

- 顶层错误边界提供恢复草稿与导出备份入口。
- 面向用户的信息不展示堆栈；开发模式可输出结构化控制台日志。
- 正式版不上传日志。用户主动导出的诊断信息必须先预览，并排除作品文本、封面等私人内容。

## 9. 构建与 CI

每次合并必须运行：

```text
format check → lint → typecheck → unit/component tests → production build
```

主分支或发布标签额外运行 Playwright 跨浏览器关键流程。构建产物必须是可部署到任意静态托管的相对路径资源，并生成依赖许可证清单。

## 10. 后续平台

- v0.2：Tauri 包装现有 Web 前端；M1 桌面壳与平台边界已完成，M2 接入原生文件系统适配器。
- v0.3.0：增加独立的小红书小工具入口与离线 ZIP 产线；复用纯领域和卡片模型，但以 Chrome 61 经典脚本、兼容 CSS、相对资源及 `window.xhs.miniTool` 窄适配器隔离容器差异。
- v0.4：先评估响应式 PWA 与 Tauri Mobile；仅当 Web 代码复用、插件成熟度或体验不达标时再考虑 Flutter。
- 动漫/游戏产品应复用通用评价引擎，但使用独立领域预设、规则和品牌入口。

### 10.1 V0.3.0 小红书小工具边界

小工具构建与 Web/Tauri 共享 `domain`、Archive v2 类型和 `CardViewModel`，但拥有独立入口、平台服务实现和输出目录。构建产物不得导入 Tauri、浏览器下载或外部导航；原生能力只允许通过显式用户操作调用 `writeTempFile` 与 `saveImageToPhotosAlbum`。首版默认不调用 `postNote`。

```text
React feature → MiniToolPlatformServices
              ├─ local cache → localStorage / IndexedDB（非永久）
              ├─ media input → image/video-capable system picker（本项目只用图片）
              └─ image save → writeTempFile → saveImageToPhotosAlbum
```

发布 ZIP 根目录只含一个 `index.html` 入口及允许类型的相对资源，最终 JS 必须是 ES2017 / Chrome 61 可执行的外部经典脚本。网络、Worker、WASM、远程资源、外链和任意文件下载均不得进入依赖图。更详细的构建、测试、性能和发布契约见 [V0.3.0 小红书小工具开发计划](./23_V0.3.0_小红书小工具开发计划.md)。

## 11. V0.2 M1 桌面边界

### 11.1 构建与版本

- `package.json` 是发布版本的唯一人工维护来源；Vite 编译常量、前端“关于”信息、`package-lock.json`、Cargo 包版本和 Tauri 清单通过 `npm run check:versions` 校验一致。
- Web 与桌面复用同一 `src/`；`npm run build:web` 生成静态前端，`npm run desktop:dev` 启动开发壳，`npm run desktop:build` 生成 Windows x64 NSIS 候选包。
- Tauri 标识固定为 `com.xdrate.music`，产品名为 `XDRate Music`，发布者技术标识为 `Kehun_EdTech`；NSIS 安装范围为 `currentUser`。

### 11.2 平台适配器

`src/platform/contracts.ts` 定义运行环境、文本打开、文本保存、二进制保存和最近文件能力。浏览器与桌面入口分别实现该契约，业务领域和评分算法不得导入 Tauri API。M1 桌面适配器有意复用浏览器下载行为；M2 只替换适配器实现，不改变领域调用方。

```text
React feature → PlatformServices contract
              ├─ Browser adapter → input / download
              └─ Desktop adapter → M1 browser fallback; M2 native implementation
```

### 11.3 桌面工作区状态

桌面文件状态由独立纯 reducer 管理，不写入 Archive：`currentPath`、`currentRevision`、`lastSavedRevision`、`dirty`、`pendingOperation` 和 `lastError`。新建、打开、编辑、保存、另存、失败和取消均有状态转换测试；保存失败不得回滚或污染评价数据。

### 11.4 M1 最小权限

- `src-tauri/capabilities/main.json` 仅绑定 `main` 窗口，权限数组为空。
- 不安装文件、对话框、Shell、进程、HTTP、更新器或任意网络插件。
- 生产 CSP 不允许外部网络源；开发 CSP 仅放行本机 Vite 与 WebSocket。
- `npm run check:desktop-config` 阻止上述边界被静默扩大。M2 若新增权限，必须按具体命令和文件范围逐项声明并增加安全测试。

### 11.5 M3 未保存修改保护

`unsavedChangesGuard.ts` 是与界面和 Tauri 解耦的纯决策层，统一处理 `new / open / close / exit` 与 `save / discard / cancel` 的组合。界面只在工作区 `dirty=true` 时调用该决策层；保存成功才运行挂起动作，保存取消或失败始终返回“不继续”。

`PlatformWindowLifecycle` 只暴露当前窗口关闭请求监听、显式关闭与设置标题，不向业务层暴露任意窗口控制。桌面适配器使用 Tauri `onCloseRequested`，批准关闭后设置一次性旁路再调用 `close()`，避免程序化关闭重新触发保护循环；标题只包含作品名或文件基名及脏标记。能力清单在 M2 的 `allow-native-files` 之外仅增加 `core:window:allow-close` 与 `core:window:allow-set-title`，仍不授予 shell、进程、任意文件系统、网络或 updater 权限。
