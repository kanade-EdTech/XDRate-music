# 版本路线重排与后续开发计划

状态：现行路线；自 2026-09-22 起覆盖旧版 v0.4.0 规划

## 1. 路线调整结论

产品不再在 0.4.0 提前实现独立 App 实体。原“移动 App 验证版”计划撤回，独立 App 实体、安装包、原生生命周期和商店发布统一推迟到 2.0.0。这样可以先把分享闭环、领域评分模型和小程序形态验证清楚，避免在产品边界尚未稳定时承担多端原生维护成本。

新的主路线为：

```text
0.3.x  音乐评分器：桌面 / 小红书小工具 / Bili Toy
  ↓
0.4.0  分享机制完善：分享卡、导出、系统分享、平台交接与恢复
  ↓
0.5.0  游戏评分试验版：验证游戏领域包与评分规则
  ↓
1.0.0  XDRate：音乐主线 + 动漫独立试验；书籍/影视保留领域契约
  ↓
1.1.0  微信小程序：在多领域模型之上适配微信容器
  ↓
2.0.0  独立 App 实体：原生安装包、生命周期、系统能力与商店发布
```

## 2. v0.4.0：分享机制完善

### 目标

- 把当前评分卡稳定地变成可分享内容，而不是提前做独立 App。
- 统一预览、PNG 导出、相册保存、系统分享和平台交接的数据契约。
- 明确分享取消、失败、权限拒绝、返回恢复和重复操作的结果分类。
- 保持离线优先，不引入账号、云同步或公开社交后端。

### 开发范围

1. 11 种比例下的分享卡版式、文字截断、长文案和图片质量继续收口。
2. 导出文件命名、分辨率、透明度、相册保存和系统分享适配器统一。
3. 分享前确认页、字符计数、隐私说明、调用前持久化和取消后的完整恢复。
4. 桌面、MiniTool、Bili Toy 使用各自平台适配器，共享评分、卡片和错误分类契约。
5. 增加分享链路的自动化测试、真机测试清单和可追溯导出证据。
6. 在分享确认页增加“个人签名档（可选）”；为空时不占布局、不参与评分，预览、PNG、相册和平台交接保持一致。

### 明确不做

- 不制作 Android/iOS 独立 App 安装包。
- 不引入 Tauri Mobile、Flutter 或原生商店发布流程。
- 不公开完整动漫、书籍、影视评分器。
- 不在本版承诺平台自动公开、预约发布或社交账号联动。

### 完成门槛

- 预览与导出逐像素/结构一致；所有 11 种比例通过无溢出门禁。
- 分享成功、取消、拒绝、失败、返回和重试均可区分且不丢草稿。
- 既有音乐算法、Archive Schema 和模板数据兼容。
- MiniTool ZIP、Toy 包和桌面构建各自通过平台审计。

## 3. v1.0.0：XDRate 音乐主线与动漫独立试验

### 产品定位

`XDRate` 不在 1.0.0 重做所有产品。音乐继续作为现有主线；动漫作为第一个独立领域试验，单独验证评价轴、视觉语言、空状态、卡片和分享闭环。书籍与影视先保留领域契约和研究夹具，待动漫证据评审后再决定公开入口。每个领域通过声明式领域包提供默认评价轴、作品字段、分数规则、文案和卡片标签；通用评分引擎、存档和导出链路保持共享。

### 兼容式演进策略

- 不把 1.0.0 定义为全产品重做；保留音乐主线和已验证的 0.x 交互。
- 以独立动漫试验入口验证领域包、视觉和交互，必要时并行开发，不直接覆盖旧入口。
- 先锁定评分核心、Archive、卡片和分享契约，再迁移可复用的页面与交互。
- 新前端必须能读取旧版本存档，并对导出结果提供兼容性快照。
- 删除或替换旧入口前，必须通过领域、导入、导出、分享、无障碍和回滚门禁。

### 1.0.0 开发范围

- 为动漫独立试验建立经过产品确认的默认轴、扣分语义、空状态文案和卡片视觉。
- 书籍、影视先作为契约/研究夹具，不提前承诺公开完整产品；游戏试验继续以 0.5.0 领域夹具为边界。
- 动漫试验使用第一主色 `#66CCFF`，并评估 `66`、`CC`、`FF` 的排列组合：`#66CCFF`、`#66FFCC`、`#CC66FF`、`#CCFF66`、`#FF66CC`、`#FFCC66`；每种组合都要通过对比度、可读性、浅/深背景和 PNG 导出一致性检查。
- 支持领域切换、自定义评价轴、领域模板和领域化分享卡，同时保证音乐 v0.3.x 的结果、存档和卡片继续可迁移、可复现。
- 建立领域级测试夹具、算法黄金样例和版权/素材边界。

## 3.5. v0.5.0：游戏评分试验版

0.5.0 是领域模型的试验版，不是完整 1.0.0 UI 重做。它在现有前端中加入游戏领域最小闭环，用来验证“领域包 + 通用评分引擎 + 领域卡片”的可行性。

- 建立游戏领域定义、作品字段、默认评价轴、评分理由和可选扣分规则。
- 复用音乐版算法、存档和导出管线，不复制一套游戏专属评分代码。
- 以内部测试和可选入口为主，不承诺完整游戏数据库、联网资料或社区榜单。
- 记录游戏领域对长文本、封面、版本/平台字段和评分卡排版的新增需求，为 1.0.0 前端重做提供输入。
- 0.5.0 的成功标准是领域契约可验证，不是游戏领域内容数量。

### 开发范围

- 冻结 `DomainDefinition`、领域包注册、Schema 迁移和评分规则接口。
- 建立游戏领域夹具、版本/平台字段、默认轴、扣分语义和空状态文案。
- 验证游戏长文本、封面和领域化卡片排版，同时保持音乐 v0.3.x 结果、存档和卡片可迁移、可复现。

### 1.0.0 不包含

- 独立原生 App 实体；继续复用 Web、桌面、小工具或 Toy 入口。
- 未研究的政治、敏感身份或高风险领域默认规则。
- 书籍、影视和游戏的完整公开产品，以及一次性替换音乐主线的全新前端。
- 云端账号、排行榜、在线素材库和自动化公开发布。

## 4. v1.1.0：微信小程序

- 将 1.0.0 多领域评分器适配为微信小程序容器。
- 复用领域内核、评分算法、卡片模型和本地草稿边界；单独实现微信文件、相册、分享和生命周期适配器。
- 先以音乐领域完成最小闭环，再开放动漫、书籍、影视入口。
- 对微信审核、分包、包体、权限、隐私说明、分享卡和真机矩阵建立独立门禁。
- 不把微信 API 反向耦合到领域核心；所有能力通过窄平台服务接口接入。

## 5. v2.0.0：独立 App 实体

只有在 1.1.0 微信小程序闭环完成、领域模型稳定、分享机制和数据迁移证据充分后，才启动独立 App 实体。

- 冻结 Android/iOS 产品身份、包名、安装升级和签名策略。
- 评估 Tauri Mobile、Flutter 或其他原生壳，不预设技术答案。
- 实现离线安装、系统文件、相册、分享、后台恢复、权限和崩溃恢复。
- 建立商店隐私、权限、崩溃监控和发布回滚流程。
- 独立 App 必须复用 1.x 的领域、算法、Schema 和卡片契约，不复制一套业务逻辑。

## 6. 版本边界与决策规则

| 版本 | 核心问题 | 主要交付 | 明确不提前承担 |
| --- | --- | --- | --- |
| 0.4.0 | 分享是否可靠 | 分享卡、导出、保存、系统分享、恢复 | 独立 App、多领域公开产品 |
| 0.5.0 | 游戏领域契约是否成立 | 游戏评分试验版与领域夹具 | 完整新前端、联网数据库 |
| 1.0.0 | 动漫独立试验与共享领域模型是否成立 | 音乐主线 + 动漫试验版；书籍/影视领域契约 | 原生 App、微信容器、所有领域一次性公开 |
| 1.1.0 | 微信容器是否可承载 | 微信小程序版本与审核门禁 | 独立 App 商店发布 |
| 2.0.0 | 是否值得做实体 App | Android/iOS 安装包与原生闭环 | 未经 1.x 证据验证的业务重写 |

旧文档中“v0.4.0 独立移动 App 验证版”的表述均以本文件为准；历史执行记录保留原状，但不得继续作为当前开发入口。

## 7. 当前下一步

1. 关闭 0.3.3 Toy 与 MiniTool 的当前交互问题，并保存可追溯包体。
2. 按 [V0.4.0 分享机制实现计划](./41_V0.4.0_分享机制实现计划.md) 建立 `codex/v0.4.0-sharing` 分支，先做快照失效、恢复幂等和失败分类，不引入原生 App 工具链。
3. 建立 `codex/v0.5.0-game-rating`，以最小游戏领域夹具验证领域包。
4. 在 0.5.0 证据通过后建立动漫独立试验入口，保留音乐主线，禁止直接覆盖旧前端。
5. 在 1.0.0 领域评审完成后再建立微信小程序适配分支。
6. 2.0.0 仅在 1.1.0 的真实使用证据和维护预算评审通过后立项。
