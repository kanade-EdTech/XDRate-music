# V0.3.0 M1 小工具入口与平台边界执行记录

状态：工程实现与自动化闭环完成；小红书真实容器复验待执行

日期：2026-09-05
分支：`codex/v0.3-minitool-m0`

## 1. 结论

M1 已把 M0 容器探针升级为独立、离线的小工具编辑入口。最终依赖图复用评分领域代码，但不导入 Tauri、桌面文件服务、浏览器下载或 `html-to-image`。自动化已经证明编辑、百分制计算、草稿恢复、PNG 工程图和相册桥接契约成立；这不替代官方模拟器、Android 8.1/WebView 61、当前 Android 与 iOS 小红书宿主验收。

## 2. 本轮实现

- 独立小工具单页壳：中英切换、作品信息、简易/专业模式、整星分项、分项理由、香蕉皮扣分、总体评价与个人故事。
- 评分语义：未评分轴为 `0` 且不计入综合分；已评分为 1–10 整星；综合分继续使用 `music-linear-100-v4` 并显示一位小数。
- Chrome 61 ID 回退：优先 `crypto.randomUUID`，其次 `crypto.getRandomValues`，最后使用时间戳与进程内序号，不再假定旧 WebView 支持 `randomUUID`。
- 本地草稿：使用独立键 `xdrate.music.minitool.workspace.v1`；300 ms 防抖写入；严格验证版本、字段、长度、评分范围和条目上限；损坏数据隔离，存储失败不清空内存状态。
- 平台边界：`MiniToolPlatformServices` 只暴露桥接存在性检查与 PNG 相册保存；相册链固定为完整 PNG Data URI → `writeTempFile` → 本地 `filePath` → `saveImageToPhotosAlbum`。
- 图片边界：用户封面在 M1 仅以 Blob URL 内存预览，切换或卸载时释放；不写入草稿。正式裁切、压缩和 11 比例卡片属于 M2/M3。
- 移动兼容基础：关键控件高度至少 44 CSS px；十颗星在单行弹性收缩；不依赖 hover、Flex `gap`、`clamp()`、`aspect-ratio` 或现代颜色函数。

## 5. 未完成与真实验收边界

- M0 尚缺设备、系统、小红书与 WebView 版本记录，以及 Android 8.1/WebView 61 和官方 PC 模拟器证据。
- 用户提供的 Android 宿主截图证明 M0 启动、滚动、字体、桥接注入和 4:5 PNG 生成，但尚不能证明相册中存在真实文件。
- M1 新编辑入口尚需在真实小红书宿主复验：输入法、十星单行、长中英文、重开恢复、拒绝/取消/成功保存和后台恢复。
- M1 的 Canvas 输出明确标注为工程验证图；正式 11 比例评分卡、内容自适应与预览一致性属于 M3。
- 封面仍未持久化、裁切或压缩，模板与偏好恢复也尚未实现，进入 M2 前不得把 M1 称为完整产品。
