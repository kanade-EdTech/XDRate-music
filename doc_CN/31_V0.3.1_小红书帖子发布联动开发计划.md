# V0.3.1 小红书帖子发布联动开发计划

## 1. 决策与目标

产品负责人已批准在 **v0.3.1** 中开发由用户主动触发的 `window.xhs.miniTool.postNote` 联动。已经发布或进入验收的 v0.3.0 保持不可变，继续只提供本地编辑、评分卡 PNG 生成和相册保存。

v0.3.1 的目标是：用户生成评分卡后，能够在明确确认将要提交的图片和文字后进入小红书原生发帖流程。小工具不得后台发布，也不得把原生接口受理误报为帖子已经公开发布。

## 2. 范围

### 必须实现

- 复用当前正式评分卡模型和 11 种比例，使用生成完成的 PNG 数据 URI 作为图片资源。
- 提供独立发布确认页，展示标题、正文、标签和全部待提交图片。
- 只有用户点击最终确认操作后才能调用 `postNote`。
- 调用前自动保存最近草稿和当前发布参数，保证离开容器后可以恢复。
- 强制标题最多 20 个 Unicode 字符、正文最多 1000 个 Unicode 字符、图片 1–18 张。
- 分别呈现“已进入小红书发布流程”“用户取消”“调用失败，可重试”，不宣称帖子已经发布成功。
- 保持离线 ZIP、零后端、零遥测和 Chrome 61 / ES2017 兼容基线。
- 中文与英文 UI、键盘操作、读屏名称、焦点恢复和安全区适配同时交付。

### 本版本不做

- 不代替用户完成最终公开发布操作。
- 不读取用户的小红书账号、帖子列表、点赞或评论。
- 不上传到自建服务器，不生成远程图片 URL。
- 不自动添加未经用户确认的话题、位置、提及或营销文案。
- 不承诺从 Bridge 回调获得帖子 ID 或公开发布状态。

## 3. 用户流程

1. 用户完成评分并生成正式评分卡 PNG。
2. 用户选择“发布到小红书”。
3. 应用打开确认页，并根据作品名预填标题、根据总体评价与个人故事预填正文；所有文本均可修改。
4. 应用实时显示字符数、截断提示、图片数量和隐私说明。
5. 用户点击“去小红书发布”。应用先保存最近草稿和待发布参数，再执行一次 `postNote`。
6. Bridge 受理时显示“已进入小红书发布流程”；取消时回到确认页且保留内容；失败时保留内容并提供重试。
7. 用户回到小工具后，可以继续编辑、重新生成图片或再次主动发起发布。

## 4. 核心算法导出

纯算法位于 `src/minitool/postNotePayload.ts`，其公开契约为：

- `POST_NOTE_LIMITS`：标题、正文和图片数量的唯一限制来源；
- `PostNoteDraft`：UI 传入的待发布内容；
- `MiniToolPostNotePayload`：传给原生 Bridge 的序列化参数；
- `BuildPostNotePayloadResult`：显式成功或失败结果；
- `isPostNotePngDataUri()`：完整 PNG Data URI 验证；
- `buildPostNotePayload()`：省略全空白可选字段、保留非空文本原貌、按 Unicode 码点安全截断、验证 1–18 张图片并生成固定 `photo_publish` 参数。

该模块不访问 DOM、React、本地存储或 JSBridge，也不执行发布。UI 可以在最终确认前安全调用它，并根据 `truncation` 显示精确提示。Bridge 适配器只能接收已经通过该算法验证的参数。

## 5. 模块边界

| 模块                 | 职责                                  | 禁止事项                           |
| -------------------- | ------------------------------------- | ---------------------------------- |
| `postNotePayload.ts` | 参数限制、验证和确定性构建            | 调用 Bridge、改变存储、显示 UI     |
| `minitoolBridge.ts`  | 能力探测、单次原生调用、取消/失败归类 | 拼接业务文案、静默重试             |
| 发布确认 UI          | 预填、编辑、预览、显式确认、状态反馈  | 绕过算法或自动调用                 |
| 本地存储             | 保存最近草稿和待发布参数              | 保存 Bridge 返回的虚假“已发布”状态 |

相册保存能力和帖子发布能力必须分别探测。设备可以支持其中一个而不支持另一个，不能继续用“两个相册函数都存在”作为 `postNote` 的前置条件。

## 6. 里程碑

| 里程碑          | 工作内容                                         | 完成标准                                   |
| --------------- | ------------------------------------------------ | ------------------------------------------ |
| M0 核心契约     | 决策入档、双语计划、纯参数算法、单元测试         | 不依赖 Bridge；边界值和 Unicode 用例通过   |
| M1 平台适配     | 独立探测 `postNote`；受理、取消、失败分类        | 不影响原相册保存；模拟 Bridge 测试通过     |
| M2 确认体验     | 双语确认页、字符计数、隐私说明、草稿先保存       | 未最终确认绝不调用；取消后内容完整恢复     |
| M3 闭环验证     | 评分卡接入、11 比例、自动化、读屏和焦点          | 预览图片与提交图片逐字节一致；回退路径通过 |
| M4 真机与候选包 | Android 8.1 / 当前 Android / iOS 18.4+、ZIP 审计 | 平台审核材料、权限矩阵和精确候选包全部通过 |

2026-09-06，产品负责人决定跳过独立 M3 阶段并直接进入 M4。该决定只取消独立里程碑和中间包，不豁免质量门禁；评分卡接入、11 比例逐字节一致性、读屏、焦点和回退路径全部并入 M4 验收。

## 7. 验收门禁

- `postNote` 只能出现在一次明确点击的同步调用链中。
- 没有图片、超过 18 张或存在无效图片时阻止调用并给出可操作提示。
- 标题和正文的实际提交值与确认页完全一致；任何自动截断都必须在最终点击前可见。
- 原生取消不是错误，不丢失草稿，不循环重试。
- Bridge 不可用时仍可生成 PNG 和保存相册，不展示不可执行的成功状态。
- 本地编辑阶段不向小红书提交文字或图片；确认页必须说明最终操作将把所示数据交给小红书。
- 最终 ZIP 仍须通过根目录 `index.html`、经典脚本、相对路径、CSP/联网字符串、体积和逐字节一致性审计。
- 自动化通过后仍必须完成精确候选包的真实设备发帖、取消、返回和失败复测。

## 8. 版本与发布策略

- v0.3.0 RC 和已发布包不修改、不重打、不复用哈希。
- v0.3.1 使用新的 ZIP 名称、版本标识、清单、SHA-256 和真实设备记录。
- 在 M4 全部门禁完成前，界面和文档只能称为工程候选，不得对外宣称帖子发布闭环已经验收。
