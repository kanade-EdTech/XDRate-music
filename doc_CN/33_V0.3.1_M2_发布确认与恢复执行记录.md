# V0.3.1 M2 发布确认与恢复执行记录

## 1. 结论

M2 已把 M1 的窄 `postNote` Bridge 接入双语发布确认页。用户必须先生成评分卡，再检查或修改标题、正文、标签和待提交图片，最后通过一次明确点击进入小红书原生发帖流程。

Bridge 返回“已受理”只表示已经进入原生发帖流程，不代表帖子公开发布。当前产物仍是 v0.3.1 工程构建，不是经过真机验收的候选 ZIP，也不得覆盖或重打已冻结的 v0.3.0 RC.1。

## 2. 确认页与数据边界

- 标题默认取作品名，正文默认组合总体评价与个人故事，标签为空；三者均可修改。
- 标题上限为 20 个 Unicode 码点，正文上限为 1000 个 Unicode 码点；计数、截断和最终参数共用 `postNotePayload.ts` 的同一规则，不会拆开代理对字符。
- 确认页展示当前生成的评分卡 PNG、字符计数和明确的隐私说明。
- 本地编辑和打开确认页不会调用 `postNote`。只有“去小红书发布”的最终操作才触发一次原生调用。
- 提交参数固定为 `photo_publish`，图片仍使用本地生成的完整 PNG Data URI；不上传到自建服务器，也不读取相册或账号数据。

## 3. 调用前持久化

最终操作的同步调用链先保存两个独立记录：

1. 当前完整工作区草稿，继续沿用小工具最近草稿存储；
2. 待发布参数，写入版本化键 `xdrate.music.minitool.pending-post.v1`，包含标题、正文、标签和完整图片数据。

只要任一保存失败，界面就显示可操作的存储失败状态，并阻止 Bridge 调用。这样不会在原生页面打开后才发现待发布内容无法恢复。

## 4. 取消、失败与返回

| 状态             | 用户看到的结果               | 内容处理                           |
| ---------------- | ---------------------------- | ---------------------------------- |
| `accepted`       | 已进入小红书发布流程         | 保留当前确认内容；不宣称已公开发布 |
| `cancelled`      | 已取消，可继续编辑或重试     | 标题、正文、标签和图片全部保留     |
| `failed`         | 调用失败，可再次主动尝试     | 内容全部保留；不静默重试           |
| `storage-failed` | 无法安全保存，未进入发布流程 | 内容保留，原生调用次数为零         |

页面刷新时会校验并恢复待发布记录，同时恢复对应评分卡预览。损坏、缺图或版本不匹配的记录不会进入可提交状态。
