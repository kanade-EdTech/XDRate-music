## 1. 验收结论

新建、打开其他存档、关闭窗口和退出应用已共用同一未保存修改保护。工作区干净时动作直接执行；工作区存在未保存修改时显示“保存并继续 / 放弃修改 / 取消”对话框。自动草稿仍是恢复副本，不被视为用户文件已保存。

## 2. 统一决策矩阵

下表适用于 `new`、`open`、`close`、`exit` 四个入口：

| 用户选择   | 保存结果 | 是否执行原动作 | 当前数据与窗口                           |
| ---------- | -------- | -------------- | ---------------------------------------- |
| 保存并继续 | 成功     | 是             | 已写入用户文件，然后新建、打开或关闭     |
| 保存并继续 | 取消     | 否             | 完整保留，继续显示未保存状态             |
| 保存并继续 | 失败     | 否             | 完整保留；对话框内显示错误，可重试或取消 |
| 放弃修改   | 不保存   | 是             | 不写磁盘，随后执行原动作                 |
| 取消       | 不保存   | 否             | 完整保留，焦点回到触发控件               |

其中“关闭窗口”来自系统标题栏关闭请求，“退出应用”来自界面上的退出入口。二者使用相同决策但保留不同说明，便于后续菜单/快捷键复用。

## 3. 实现边界

- `src/application/workspace/unsavedChangesGuard.ts`：纯决策层，覆盖 4 个入口和 3 个选择；保存取消或失败不得继续。
- `src/features/rating-editor/components/UnsavedChangesDialog.tsx`：语义化模态对话框；默认聚焦取消，支持 `Escape`，限制 Tab 焦点并在关闭后归还焦点。
- `src/features/rating-editor/RatingEditor.tsx`：保存动作返回明确状态，挂起受保护动作；新建、打开、退出和 Tauri 关闭请求全部接入同一守卫。
- `src/platform/contracts.ts` 与桌面适配器：新增最小 `PlatformWindowLifecycle`，只允许监听当前窗口关闭和显式关闭。
- 浏览器运行时：脏状态通过原生 `beforeunload` 警告保护刷新、关闭和离页；受浏览器安全规则限制，具体文案与按钮由浏览器决定。
- Tauri 能力：在 M2 的 `allow-native-files` 外只增加 `core:window:allow-close`；未增加 shell、进程、任意文件系统、网络或 updater 权限。
