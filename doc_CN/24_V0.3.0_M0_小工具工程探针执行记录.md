## 1. 本轮结论

M0 已建立可复现的小红书小工具独立构建、静态审计、确定性 ZIP 打包和桥接测试链。当前产物是用于验证容器契约的最小工程探针，不是完整产品，也不是公开发布候选包。

已由自动化证明的范围：

- ZIP 根目录直接包含唯一 `index.html`；
- React 入口构建为外部经典 IIFE 脚本，脚本在 `<head>` 中使用 `defer`；
- HTML、CSS 与 JS 只引用包内相对资源；
- 最终产物不包含远程 URL、网络请求、自定义原生消息协议、Worker、WASM、动态模块或内联脚本；
- 本地草稿可写入和恢复，用户图片使用 Object URL 预览并释放；
- Canvas 2D 可生成完整 PNG Data URI；
- 相册保存严格执行 `writeTempFile({ data })` → 本地 `filePath` → `saveImageToPhotosAlbum({ filePath })`；
- 桥接不可用、非法 Data URI、远程临时路径与用户取消会得到分型错误。

尚未证明的范围：

- 官方小红书 PC 模拟器能否导入并启动该 ZIP；
- Android 8.1 / Chrome-WebView 61 的真实 React、中文字体、输入、触控和 Canvas 运行；
- 已提供截图的 Android 设备具体型号、系统版本、小红书版本与 WebView 版本；
- 当前 Android 与 iOS 小红书容器的真实相册授权、拒绝、取消及恢复；
- 完整 XDRate 编辑器、评分域、11 种比例与生产级 PNG 适配器在小工具中的表现。

## 5. 发现与处理

1. Vite 默认生成模块入口，不符合容器契约。小工具构建改为经典 IIFE，并审计最终 HTML而非源码。
2. 经典脚本若放在 `<head>` 且无 `defer`，会在根节点创建前运行。E2E 捕获该问题后，构建阶段强制增加 `defer`。
3. React 19 运行时会读取 `navigator.connection` 估算预加载速度。小工具最终包在构建阶段将该探测替换为无能力分支，避免触碰禁用设备 API。
4. React Scheduler 使用包内 `MessageChannel` 调度。审计只禁止 `window`、`parent` 或 `top` 的 `postMessage` 自定义原生协议，不误禁标准的同页 MessagePort 调度。
5. React 生产运行时原带有 `react.dev` 错误帮助 URL 字符串。它不会主动请求网络，但为避免平台字符串扫描误判，构建阶段将其替换为本地错误标识；审计器对非 W3C DOM 命名空间的 URL 字符串设为硬错误。
6. 生成目录一度被通用 ESLint 扫描；`dist-minitool/` 与 `artifacts/` 已加入忽略清单，源码仍由 ESLint 覆盖。
